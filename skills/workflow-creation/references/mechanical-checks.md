# 机械层 / 形式要件下沉方法论

> workflow-creation skill 按需参考。词形/结构/存在性类判据下沉写侧机械层（append-trace 当场拒）的主题。原 rubric-design.md §3.5 机械下沉部分按主题迁此；括注原编号供溯源。

## 1. 词形判据下沉机械层，judge 只判真值/质量（原 §3..5 #13）

**词形判据下沉机械层，judge 只判真值/质量**（2026-07-30 v2.27，弱模型优先原则）：写判据时逐条问「这条正则/集合运算能判吗」——能判的不该花 judge 调用（每轮 ~13k in + ~36s）还判不稳（天然方差）。实例：方案名词扫描（实现侧名词真值=codegraph 符号表+git 文件名，append-trace 落库当场拒并点名，比 judge 便宜且零方差）、源步条目 ID 传导覆盖核对（集合包含，judge #1 的活正则化）。这是四桶分工「能机械推导→脚本」对 gate 的兑现：机械预检在 append-trace（fail loud 当场返工），judge 只剩它判得了的——真值与质量（空泛/编造/同义反复）。注意精度纪律：词表只收强信号（ASCII 边界匹配——`\b` 对 CJK 不可靠；规范文档扩展名豁免——合法引用源）。

## 2. 机械规则先过重放分隔度检验，过不了就升级杠杆（原 §3..5 #15）

**机械规则先过重放分隔度检验，过不了就升级杠杆**（2026-07-31 v2.32，tail_volume plan:1 子5/plan:2 子4 复盘）：给机械预检设计信号前，用**真实被 block 载荷 + 真实通过载荷**测候选信号间隔——实测「+」计数：被 block 4~17 vs 通过 0~3，margin=1 的阈值（≥4）= 调参数式修复（数据分布一变就破）；且词形相同（名词枚举 "backtest_results + 4 处模板" vs 动词串联 "跑测试 + commit"）机械不可分。分隔度不够不硬上，升级判据钉死杠杆（`_ATOMIC_ITEM_RULE`：按独立性判不按词形判）。**判据自相矛盾识别**：两个形式要件不能同时满足（「八字段同句携带」×「每项 ≤1 句」——字段全带必产出枚举形态，枚举必被判复合）→ 合法产出无通过路径，judge 判词会开始失真（att1 幻觉「数十个『。』断句」实际 ≤1 个——判不出来就换理由判）。**重放扩面到语义判据**（2026-08-01 v2.36，`_CAUSAL_CHAIN_EVIDENCE_RULE` 初版两缺陷当场逮住）：gate **文本**变更同样必跑重放——live judge × 真实被 block 载荷 + 真实通过载荷 × 新 gate，判决方向须与原始一致，不一致=判据变了味不是变了词。两个典型翻车反模式（判据收紧时高发）：①**越界吞并下游职责**——「主链每环实际证据」被读成「根因必须已证明」，把子3/子4 的取证裁决吞成子2 义务（原 pass 轮被翻案 block）；②**豁免分支全量化规避**——给「未实测」开了候选假设豁免，全部链环写成候选形态即合法落入豁免（原 block 轮被放水 pass）。教训两条：判据给豁免条款时，重放必测「全量化该豁免」的规避载荷；判据涉阶段分工时，重放必测「按要求做到底」是否会越界。**新判据无历史载荷时构造双向最小载荷**（2026-08-02 v2.40 分档判据落地）：全新判据没有被 block/通过的真实载荷可重放——构造最小真实感载荷双向测：合理例→须 PASS（防判据无通过路径）、典型违规例→须 BLOCK（防判据无牙齿）；**判词质量也是验证对象**——BLOCK 判词须精确引用新条款（v2.40 实例：「数值合理性属外部知识依赖却标 none」+改写范例），判词空泛/绕开新条款=判据没被 judge 内化的信号，回去改判据文案。**配置变更重放必带对照组（2026-08-02 v2.44 judge 禁思考链加固实例）**：非判据类配置变更（judge env/harness 参数）的验收重放，单测新配置判出翻案时**不归因配置**——先跑同重建旧配置对照。实测：no-thinking judge 对真实通过载荷判 BLOCK（疑似退化），thinking-on 对照同判 BLOCK——翻案来自重放重建差异（model_output 桩/artifact 裁剪/缺 prior_verdicts），非思考开关。无对照的翻案结论会把重放保真度问题误判成配置退化。**「通过载荷」保真度陷阱（2026-08-02 v2.50 实例）**：从 mech 层测试 fixture 借来的通过载荷比生产真实通过 trace 薄（fixture 为机械校验精简过，只覆盖本层要件），live judge 会按 gate 其它要件（逐原子竞争假设覆盖）照判 BLOCK——新旧文本对照同判 BLOCK 才结案为重放保真度问题；通过载荷优先取生产真实通过 trace，借 fixture 时先对照 gate 全要件清单补全。**抑制类钉句必须双侧（2026-08-02 v2.52 实例，重放第五次逮住上线前缺陷）**：给 judge 加「X 已机械校验勿重复判」钉句时，judge 会把 scope 枚举项的词（「结论前缀」）泛化成整域免判（结论无出处推断被放过 PASS）——钉句必须双侧写：枚举项勿重复判 + **非枚举项照判不误**；重放必测「该拦的还拦」（被 block 载荷方向不变）与「免判范围不扩」（枚举项所在域的其它违规照 BLOCK）两侧。

## 3. judge 对形式要件有「实质满足」放过倾向——存在性/结构一律机械核验（原 §3..5 #17）

**judge 对形式要件有「实质满足」放过倾向——存在性/结构一律机械核验**（2026-08-01 v2.38 落地重放实证）：新 gate 要求「子代理蒸馏报告原文收录」，用无报告项的旧形态真实 trace 重放 → judge 判 PASS——**内容丰富的产物会让 judge 把形式要件当实质满足放过**（它判的是「这看起来像完成了取证」，不是「规定形态是否存在」）。凡「X 必须存在/以某形态存在」的形式要件，别指望 judge 稳定执行：下沉机械核验（存在性=JSON 键校验/标题扫描），gate 文本明示「存在性已机械校验，judge 只判真实性与质量」（对齐 v2.34 防幻觉先例）。#15 的「改判据必跑真实载荷重放」第三次连续逮住上线前缺陷（v2.36 初版两缺陷 → v2.38 形式要件放过）——重放对象从「验证判得对」扩到「**验证 judge 会执行新形式要件**」。

## 4. 形式要件机械化的前置审计：被校验字符串必须先在模型可见面有逐字单源（原 §3..5 #19）

**形式要件机械化的前置审计：被校验字符串必须先在模型可见面有逐字单源**（2026-08-02 v2.41 产物节名单源化）：给机械门挂字符串校验（ARTIFACT_CONTAINS 类）前，先 grep 全部模型可见通道（phase-rules 装配行/注入/Step.purpose）确认模型被**逐字告知**过该字符串——plan:2 装配行只说「装配 plan.md」连节名都没给，此时挂「执行步骤」节校验 = 必误 block（门拦的是模型从未被告知要写的产出）。#7（合法获取路径）在形式要件维度的同构、#17（形式要件机械化）的前置条件：机械化之前被校验形态先在可见面单源化（正解 = 单源常量 + 模板 token 渲染 + 注入动态构建，见 §3.7 #4 补段）。**连带纪律**：门收紧类变更的「连带行为变化」必披露**在飞实例**影响——已有产物按旧规格写的，下次重判撞新门（block 文案给修复动作 + state-reset 兜底，非死锁，但要写进设计文档）。

## 5. 行为禁令的闭环=写侧机械核验——「禁 X」文案必追问「能机械验证没发生 X 吗」（原 §3..5 #20）

**行为禁令的闭环=写侧机械核验——「禁 X」文案必追问「能机械验证没发生 X 吗」**（2026-08-02 v2.42→v2.43，fetch-prompt 骨架落盘）：禁令文案只约束「读它的模型」——purpose 钉「禁自选落盘路径」后，模型重定向 stdout 自选路径则钉死形同虚设；且这种违反**不进 judge 视野**（产物内容合法，只是来路不对，judge 看产物看不出路径违规），唯一防线是提交点机械核验行为留痕（骨架文件须存在于钉死路径、mtime 不早于本节点 entered_at）。与 #17 的分工：#17 防 judge 把形式要件当实质满足放过（**判**的一侧），本条防模型绕开行为禁令（**做**的一侧）——文案钉死 → 机械核验才是完整闭环。**新机械校验复用既有三件套，不发明新机制**：EXISTS + not_before 新鲜度 + 宁纵勿枉降级（基准时间不可考 → 仅存在性）——§8.3 产物门范式直接平移，降级纪律全系统一致。**连带测试纪律**：新写侧校验挂到既有步会让既有测试连带红——在测试 helper 补正交前置（注释「本类测 X，Y 是正交前置」），不删新校验、不放宽旧断言。 **第四实例**（2026-08-04 v2.83 redteam_three_piece）：新增 mech 让既有 `test_dispatched_and_recorded_accepted` fixture（红队收录项 a 含「置信度中」缺「推理链」）连带红--修 fixture 补齐三件套（更真实的合规形态），非放宽旧断言。

## 6. 机械检查向相邻节点泛化的三原则（原 §3..5 #22）

**机械检查向相邻节点泛化的三原则**（2026-08-02 v2.48，v2.37 模式泛化首例）：同一失效模式在新节点复发（u:2 子1「意味着/隐含」无出处推断 = u:1 子2「读出后推出」同类）时，优先**复用已验证修复**而非新实验，但泛化不是照抄——①**词形只从该节点真实违规字面取**（不凭想象造词表：隐含/意味着来自 att1 原文）；②**扫描面只锚出过事的项类型**（价值/结论项才扫，who/outcome 不扫——词形在别的项里可能合法，贪宽=FP）；③**豁免口与形式要件的合法出口一一对应**（「推测」另列豁免 ↔ 要件本就说「只能标注推测另列」——机械拒不能把合法出路也堵死）；④**正则窗口/间隔同样按逐字字面定，不凭感觉**（v2.49 near-miss：「需…看」初版窗口 {0,16}，真实违规字面「需 pyarrow.read_parquet(path) + sort 看」间隔 33 字符直接漏网——词形逐字取了、窗口凭感觉定=只完成一半；定稿前拿原始未精简载荷实测候选信号命中，精简保形夹具会掩盖窗口过窄）。泛化后必跑该节点**历史真实 trace 重放**验证分隔度（违规版 BLOCK/通过版 PASS/其它工作流同节点零 FP），三侧齐了才收。

## 7. 机械信号的锚定面假设模型不按示范形态写——锚内容结构，不锚标题/措辞（原 §3..5 #21）

**机械信号的锚定面假设模型不按示范形态写——锚内容结构，不锚标题/措辞**（2026-08-02 v2.46，弱模型优先复查实证）：`causal_ring_no_untested` 只扫 q 标题含「因果链」的项，而违规词形的来源实例恰好是那个标题——**按违规实例的标题锚定 = 模型换个标题写法扫描就空转**（8/2 实例「Q4=…」式标题、链写进 a，「可能」漏到 judge 115s/10.8k tok 才拦）。修法：链识别改内容结构信号（a 含 Why/→），豁免与排除同样按结构（「假设」标题项豁免、(?<!不)可能 排除否定式）。同例正面：v2.44 红队收录核验锚「task-id 存在性」（派发即有的机械事实），不锚「已派发/等归位」措辞（词表已被「未归/仍在跑中」绕开一次）。写机械扫描时问一句：**模型完全不看示范标题/措辞重写一遍，这个信号还中吗**？分隔度检验（#15）的载荷要含「同内容不同形态」变体，不只原样重放。**分段正则同病**（2026-08-02 v2.55）：WhyN 环段切分锚 `Why\d+[:：]`，真实载荷写 `Why1=`/`Why4（根因层）=` 分段全空转——违规文本明明在 `a` 里，扫描却无一环可扫；初版重放当场逮住（真实被 block 载荷 PASS=空转信号），改项级扫描才分隔。

## 8. fail-loud 报错指路必须与文件实况一致--否则模型进 debug 死循环；解析器对模型自然写法宽容 + 报错带 repr 是两条防线（原 §3..5 #25）

**fail-loud 报错指路必须与文件实况一致--否则模型进 debug 死循环；解析器对模型自然写法宽容 + 报错带 repr 是两条防线**（2026-08-03 v2.65，tail_volume_acceleration_annualized u:1 子1 手写载荷事故）：模型绕过 `--scaffold` 手写载荷，标头粘内容同行（`【purpose】内容`，自然风格；scaffold 骨架是标头独占行）；解析器旧 regex 整行匹配把粘头行当「标头前多余内容」拒，报错「从【purpose】开始」--但文件**确实**以【purpose】开头，报错指路与实况矛盾。模型据此怀疑隐藏字节，连环用 `head|xxd`/`od`/`python3 -c` 诊断，前三者被 S15 围栏 deny（xxd/od 非白名单）、python3 被 deny（能写），8 个工具报错零产出。**三层修**：①**解析器宽容化**--标头 regex 放行粘头内容（group(2) 注入当前节首行）+ 剥文件头 BOM，模型自然写法直接通过（手写全粘头真实载荷四向验证：手写通过/BOM 通过/干净骨架向后兼容/junk 报错）；②**报错带 repr**--「首个标头前有多余内容」附 `{val[:80]!r}`，BOM/散文一眼可见，免字节 hunt；③**诊断通道对齐**--`od`/`hexdump`/`xxd` 纯只读字节查看器进 S15 白名单（`>` 已一票否决挡写意图），python3 仍拒（能写，模型改用 cat/head/od）。**原则**：fail-loud 的报错是模型的返工指令（#10 同族），指路方向与文件实况矛盾时模型无法收敛--要么解析器接受它的自然写法、要么报错让它一眼看出问题在哪；`--scaffold` 生成正确格式是第一道，但模型会绕过，解析器宽容是 defense-in-depth。**鉴别信号**：报错说「缺 X」但文件里明明有 X = 指路失真，立即查解析器/校验器是否拒了它不该拒的形态。
**v2.66 补硬杠杆（用户质询「解析器宽容是软解」后的正治分层）**：宽容化只是 defense-in-depth，根治是**堵死旁路入口**——模型手写粘头=手写格式=四桶违规（格式归脚本），正治不是接受它的格式，是让它写不了格式：fence S14 禁手写 Write `.trace-payload-*.md`（指回 --scaffold，模型只 Edit 填「待填」）+ 注入文案把 scaffold 从「推荐」升为必经路径。**分层**：主动指引（注入，第一道）→ 硬围栏（fence deny，第二道，弱模型无视指引时的可靠杠杆）→ 解析器宽容（第三道，defense-in-depth 处理 scaffold 输出的边缘 glitch）。**判别准则**：「模型绕过 X 犯错」类问题，先问能不能让绕过不可能（堵入口），而不是让绕过也能成功（宽容输出）——后者是软解，会把违规行为合法化、鼓励再犯；前者才是系统侧正治。宽容保留的前提是它处理「系统自身输出的边缘缺陷」（scaffold glitch），不是「模型的违规行为」。

## 9. 系统可见面文案（deny 指路/报错/usage）里的命令模板必须真实可跑——「系统文案教的写法必败 = 系统 bug 非模型违规」（原 §3..5 #26）

**系统可见面文案（deny 指路/报错/usage）里的命令模板必须真实可跑——「系统文案教的写法必败 = 系统 bug 非模型违规」**（2026-08-03 v2.67，tail_volume u:1）：fence S14 deny 文案教模型跑 `append-trace --scaffold`，模型谨慎补显式 name → 撞 argparse 已知缺陷（`nargs='?'` 位置参数前隔 optional 必报 unrecognized arguments）——文案模板与实际解析器漂移，模型按指路操作零产出。**鉴别信号**：报错形态是「按系统指路/报错提示操作，仍报错」时，先逐字重放文案里的命令模板，别归因模型操作。**配套**：白名单/围栏按**语义等价**放行为，不按路径——S15 只放行 `dl-cmd.sh status` 不放行引擎直调 status（dl-cmd 本就包装引擎，语义等价），路径技术性 deny 白烧一轮往返；只读操作尤其应宽（写状态操作才配窄通道）。

## 10. 幂等/防重判据的锚定方向与违规扫描相反——判「脚本产出是否已存在」锚自己写出的精确形态，宁纵勿枉
