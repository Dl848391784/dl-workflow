## 3.5 门控判据（rubric）设计方法论（改判据/写新 gate 前必读）

2026-07-25 全天 demo 实测沉淀。改任何 `Step.gate` / `gate_rubric` / judge prompt 前对照：

1. **三层分工，各判各的**：机械层判存在性（trace/hash，零成本短路）；judge 判**结构完整性**（覆盖度/对齐/引用/形式）——judge 没有项目上下文，**判得了结构、判不了真值**；真值与认可度归用户（读回确认 / 升级裁决）。别让 judge 判它判不了的东西（如「真实问题已逼出」——它无法验证）。
2. **防 Goodhart 分层**：形式要件（格式/覆盖度）可以披露给模型（进 purpose，降形式性返工）；质量判据（可观察/非编造/非空泛）**只留 gate 黑盒**。全披露 = 模型照 checklist 填表，judge 分辨力丧失（Goodhart 定律）。方法论指引（怎么取证）进 purpose，评判标准进 gate，单源常量绑定。
3. **判据必须接受「问题不成立」为合法结论**（双结论制）：只认「问题成立」的 rubric 会让诚实答案（无痛点/纯好奇）永远过不了，**逼模型编造痛点**（「好奇心缺口」式伪痛点实测被 judge 识破）。放②的判据 = 原话佐证 + 结论标记；区分「诚实无痛点」vs「懒得挖」的判据是原话佐证。
4. **裁量点必钉死**：judge 也是模型，同一证据可不同判决（who 出处三次两拒一过实测）。发现「同类证据一过一拒」→ 立即把该点写成死规则（who 出处只认用户自述；仓库事实不能证明提问者身份）。**判据留白的每一寸都是方差**。
5. **判词要指路**：block reason 不只说缺什么，还要指明返工方向（建议哪条分支/补哪类）——模型按判词一次修好，零提问返工是健康标杆。
6. **一过率不是目标，健康返工才是**：健康 = 返工 ≤1 个定向问题或零提问、绝不重问已答内容。block 有信号价值（实测一次 block 把「随便查查」逼成真问题）——门控从不 block 时要怀疑它失效，而不是庆幸。
7. **判据要求的佐证形式必须存在低成本合法获取路径**（2026-07-25 子1 校准）：要求「用户否认痛点的原话」但用户几乎不会主动声明 → 模型不敢问/没想到问就只剩编造一条路，block 循环。修法不是松判据，是**打通「问→引」路径**：purpose 强制「材料不足先 AskUserQuestion 事实性补问」+ gate 明示「补问的回答原话是合法佐证、从未被问及的『未提及』不算」。审查新判据时多问一句：模型拿到这个要求的合法证据，最便宜的正确动作是什么？如果答案是「没有」，判据本身就是在逼编造。
8. **校准看 block 性质，不看频率**（2026-07-25 子1 四连 block 案例）：高频 block 不是松绑信号，先逐条分类——形式缺失/覆盖不足/编造自述 = **该抓**（门控在工作，说明模型在试图绕过）；「要求的佐证没有合法获取路径」= **判据缺陷**（见 #7）。只有后者改判据。n=1 的 block 率不构成校准依据；step2 一过而 step1 四连 block 的不对称，正确读法是「两次判得都对」，不是「一个太严一个太松」。 完整工作示例（demo 121320fe）：用户直觉「6 次 block、零一过率=问题很大」-> 逐条核对判词 vs purpose/证据 -> 6/6「该抓」（4 次违反已披露形式要求、1 次系统缺陷诱发、1 次实质越界）、0 判据缺陷 -> 结论：不动判据，修的是披露缺口+自查提示（#9）。

9. **区分「知识失败」与「注意力失败」**（2026-07-26 demo 121320fe 复盘）：模型被指后一轮就修好 = 它**知道**规则只是没用上（注意力失败）——这类 block 的最便宜解法不是改判据，而是**提交前自查提示**（engine `selfcheck_hint(step)` 单源 = 通用段 `STEP_SELFCHECK_HINT` + 按步声明的 `Step.selfcheck` checklist，pass 续轮/block 返工/注入三通道同文）：把「judge 抓」前移为「自查抓」，省 judge 调用 + 省一轮 Stop 往返。步级化动机（demo d59d05ea，MiniMax-M3 子1 三连 block 全是已披露形式要件的注意力失败）：通用提示太抽象，步级 checklist 把「对照形式要件」落成具体逐项提问——**checklist 只列 purpose 已披露的形式要件，质量判据仍只在 gate 黑盒**（测试 `test_selfcheck_no_quality_criteria_leak` 钉死）。反之，反复讲仍犯 = 知识/能力失败，自查提示无效，只能机械拦或换模型。判据要求了但 purpose 没披露的形式要件（demo 子4「汇总声明不算记录」）属披露缺口——补上即可，属 #2 的应用，不算松判据。**二分之外的第三形态=操作化分歧**（2026-07-30 tail_volume understand:2 子4 实证）：模型**真做了**该项自查还答「是」（trace 有推理记录），但把 solution-free 核查落在谓语（「按真实数值判定=outcome」）、judge 裁量落在主语（模板文件名入主语=违规）——「被指后一轮修好」也可能是判据留白导致的操作化分歧，不是注意力失败。鉴别法：判注意力失败前先查 trace 里该项自查是否真被执行过——**执行过仍 block = 裁量点分歧**，归 #4 处理（操作化定义披露进 purpose/selfcheck，自查提示对这类无效，它已自查）；未执行才是注意力失败。**鉴别动作补两条**（2026-08-01 v2.36 子2 判型实例）：①模型把「未实测/推断」取证状态标注当合法「证据出处」答自查「是」——状态标注 vs 证据指针是高频分歧对，操作化定义要直接点名「X 不算 Y」；②**查 `.wf_fence.log` 的 deny 记录**——模型被 engage 围栏 deny 一次 Bash 后把单工具单次 deny **泛化**为「本步禁取证」（trace 自白「S15 限制 Bash 探查」），修法是 purpose 钉「合法通道是什么」（Read 合法且足够），不是扩围栏放行——围栏 deny 的过度规避副作用要算进判词/指引设计。

10. **block 文案就是模型的返工指令——基础设施失败必须区分**（2026-07-26 demo fbdb6ebd 子2 复盘）：judge 超时降级 block，模型把「judge 调用失败（TimeoutExpired）」解读为内容不合格，把**本已合格的 trace 精简重写一轮**（~2min + 十几 k tokens 白烧，下轮原样判过）。教训两条：①可重试的基础设施失败（超时/格式抖动）先在机制层重试，别转嫁成模型返工（v2.12 已实装）；②设计任何降级路径时把「模型会如何解读这个 block」算进成本——block reason 不只给 judge 看，它直接塑造模型下一轮回做什么。同理，「不做 X」的机制决策要记录**根因**（当初超时不重试防的是递归爆炸），根因消除（cwd=tempdir）后要重估，否则防御措施退化为纯损失。

11. **判据合法性是双向的：模型侧获取路径（#7）+ judge 侧可见路径**（2026-07-28 plan:1 实施实测）：judge 的输入面只有 model_output + 条件性 artifact_content——它**读不到任意文件**（design.md 这类产物它看不见）；且节点级 gate 的 artifact_content 仅当 rubric 文本含 `evidence/`（**带斜杠**）或 `skill-trace` 关键词时才喂 evidence.jsonl（`rubric_needs_evidence` 单源）。plan:2 rubric ④初稿写「与 evidence 里的设计包一致」——无斜杠不触发，judge 读不到设计包，判据沦为不可判（新测例 `test_plan2_rubric_needs_evidence_true` 当场抓住）。审查新判据多问一句：**judge 的输入面能支撑这条判据吗**？需要对照 evidence 的判据必须含关键词 + 加测例钉死；需要对照文件的判据要么改走 evidence 路径，要么该判据降级（移出 rubric）。
12. **裁量点钉死必须双侧：purpose（模型侧）+ gate（judge 侧）**（2026-07-30 v2.23→v2.24 复盘，tail_volume u:3 子4 五连 block）：#4 说「写成死规则」，但写在哪决定有没有用——v2.23 把操作化定义只披露进 purpose/selfcheck，judge 输入面仍只有一句黑盒判词，结果同一 rubric 五轮五种解释（类名入主语→实现指针段→动词词形逐轮收紧）。**漂移的主体是 judge，钉的对象就必须含 judge**——单源常量双侧引用（仓内先例：`_DS_STEP1_FORM_REQUIREMENTS` 注释明写「purpose 模型侧与 gate judge 侧都引用」）。审查钉死方案时问一句：judge 读得到这条规则吗？读不到 = 只钉了一半。
13. **词形判据下沉机械层，judge 只判真值/质量**（2026-07-30 v2.27，弱模型优先原则）：写判据时逐条问「这条正则/集合运算能判吗」——能判的不该花 judge 调用（每轮 ~13k in + ~36s）还判不稳（天然方差）。实例：方案名词扫描（实现侧名词真值=codegraph 符号表+git 文件名，append-trace 落库当场拒并点名，比 judge 便宜且零方差）、源步条目 ID 传导覆盖核对（集合包含，judge #1 的活正则化）。这是四桶分工「能机械推导→脚本」对 gate 的兑现：机械预检在 append-trace（fail loud 当场返工），judge 只剩它判得了的——真值与质量（空泛/编造/同义反复）。注意精度纪律：词表只收强信号（ASCII 边界匹配——`\b` 对 CJK 不可靠；规范文档扩展名豁免——合法引用源）。
14. **判据默认会在多轮重判中执行——轮间一致性是判据设计的一部分**（2026-07-30 v2.26）：judge 每轮全新调用**无记忆**，是裁量漂移的制度根源（不是某次 judge 发挥失常）。机制出口已建：block 判词落 evidence（kind=gate/blocked），重判喂 prior_verdicts + 一致性指令（前轮未点名放过的写法不得新判违规）。配套判词要求（#5 的深化）：**指模式不指实例**——只点名实例位置（in[6]/C1.1…）会让模型逐条打地鼠、修点名的造新雷（u:3 子4 五轮同族复发实证）；重判时判词须附 1 个正确改写范例。写判据时把「模型会按判词打地鼠」算进成本。
15. **机械规则先过重放分隔度检验，过不了就升级杠杆**（2026-07-31 v2.32，tail_volume plan:1 子5/plan:2 子4 复盘）：给机械预检设计信号前，用**真实被 block 载荷 + 真实通过载荷**测候选信号间隔——实测「+」计数：被 block 4~17 vs 通过 0~3，margin=1 的阈值（≥4）= 调参数式修复（数据分布一变就破）；且词形相同（名词枚举 "backtest_results + 4 处模板" vs 动词串联 "跑测试 + commit"）机械不可分。分隔度不够不硬上，升级判据钉死杠杆（`_ATOMIC_ITEM_RULE`：按独立性判不按词形判）。**判据自相矛盾识别**：两个形式要件不能同时满足（「八字段同句携带」×「每项 ≤1 句」——字段全带必产出枚举形态，枚举必被判复合）→ 合法产出无通过路径，judge 判词会开始失真（att1 幻觉「数十个『。』断句」实际 ≤1 个——判不出来就换理由判）。**重放扩面到语义判据**（2026-08-01 v2.36，`_CAUSAL_CHAIN_EVIDENCE_RULE` 初版两缺陷当场逮住）：gate **文本**变更同样必跑重放——live judge × 真实被 block 载荷 + 真实通过载荷 × 新 gate，判决方向须与原始一致，不一致=判据变了味不是变了词。两个典型翻车反模式（判据收紧时高发）：①**越界吞并下游职责**——「主链每环实际证据」被读成「根因必须已证明」，把子3/子4 的取证裁决吞成子2 义务（原 pass 轮被翻案 block）；②**豁免分支全量化规避**——给「未实测」开了候选假设豁免，全部链环写成候选形态即合法落入豁免（原 block 轮被放水 pass）。教训两条：判据给豁免条款时，重放必测「全量化该豁免」的规避载荷；判据涉阶段分工时，重放必测「按要求做到底」是否会越界。**新判据无历史载荷时构造双向最小载荷**（2026-08-02 v2.40 分档判据落地）：全新判据没有被 block/通过的真实载荷可重放——构造最小真实感载荷双向测：合理例→须 PASS（防判据无通过路径）、典型违规例→须 BLOCK（防判据无牙齿）；**判词质量也是验证对象**——BLOCK 判词须精确引用新条款（v2.40 实例：「数值合理性属外部知识依赖却标 none」+改写范例），判词空泛/绕开新条款=判据没被 judge 内化的信号，回去改判据文案。
16. **钉死保判对不保写对——一次通过率是独立战场，杠杆=写侧机械层+正反范例+正面退路**（2026-08-01 v2.37，钉死后 relaunch 复发实证）：#4/#12 的裁量点钉死效力止于「judge 判得对」——`_CAUSAL_CHAIN_EVIDENCE_RULE` 钉死后重跑（phase-rules 已含新规），模型仍同症两连 block（节点一次通过率 33%）。残余失败两形态与对策：①**操作化分歧往深一层**——模型有 file:line 就以为合规（「读出即事实」vs「读出后推出」未分清），对策=正/反范例直接点名形态（反例「过滤 NaN 后可能剩 1-5 天（:630-647）」——file:line 背书的只是代码文本，量级是推断）；②**prohibition-only 规则留行动洞**——模型挖不到实测证据时不知道该怎么办，只能贴「未实测/推断」标签（正是规则禁止的形态），对策=给正面退路句型（「挖不动的深层整体降格进竞争假设分支标待子3取证，主链挖到实测层即终止」）。**写判据时问一句：模型做不到这条时，规则告诉它正确的退路吗？** 只有禁止没有退路的规则，复发率不随钉死下降。词形部分同步下沉写侧机械层（#13 扩面：`Step.mech_checks` 注册表，append-trace 当场拒+指路，零 judge 成本；鉴别信号回顾=att2 模型自贴标签，机械扫描必中）。
17. **judge 对形式要件有「实质满足」放过倾向——存在性/结构一律机械核验**（2026-08-01 v2.38 落地重放实证）：新 gate 要求「子代理蒸馏报告原文收录」，用无报告项的旧形态真实 trace 重放 → judge 判 PASS——**内容丰富的产物会让 judge 把形式要件当实质满足放过**（它判的是「这看起来像完成了取证」，不是「规定形态是否存在」）。凡「X 必须存在/以某形态存在」的形式要件，别指望 judge 稳定执行：下沉机械核验（存在性=JSON 键校验/标题扫描），gate 文本明示「存在性已机械校验，judge 只判真实性与质量」（对齐 v2.34 防幻觉先例）。#15 的「改判据必跑真实载荷重放」第三次连续逮住上线前缺陷（v2.36 初版两缺陷 → v2.38 形式要件放过）——重放对象从「验证判得对」扩到「**验证 judge 会执行新形式要件**」。
18. **规则落点跟 actor 走——执行位置下沉子代理时红线必须随迁**（2026-08-01 v2.38 子3 子代理化）：「禁止探查凭证」写在子3 purpose 时执行者是主会话；外部调用移入 fetch 子代理后，主会话不再直连外部源，purpose 里的红线成空防（**子代理读不到主会话 purpose**）——随迁到 fetch-prompt 纪律（pinning 测试钉新落点）。审查任何「执行位置下沉子代理」的改动，把该步红线/禁令清单逐条过一遍：**新 actor 读得到这条吗？**
19. **形式要件机械化的前置审计：被校验字符串必须先在模型可见面有逐字单源**（2026-08-02 v2.41 产物节名单源化）：给机械门挂字符串校验（ARTIFACT_CONTAINS 类）前，先 grep 全部模型可见通道（phase-rules 装配行/注入/Step.purpose）确认模型被**逐字告知**过该字符串——plan:2 装配行只说「装配 plan.md」连节名都没给，此时挂「执行步骤」节校验 = 必误 block（门拦的是模型从未被告知要写的产出）。#7（合法获取路径）在形式要件维度的同构、#17（形式要件机械化）的前置条件：机械化之前被校验形态先在可见面单源化（正解 = 单源常量 + 模板 token 渲染 + 注入动态构建，见 §3.7 #4 补段）。**连带纪律**：门收紧类变更的「连带行为变化」必披露**在飞实例**影响——已有产物按旧规格写的，下次重判撞新门（block 文案给修复动作 + state-reset 兜底，非死锁，但要写进设计文档）。

## 3.6 运行审计方法论（review 一轮真实运行：可避免 error / 返工 / 优化点）

2026-07-26 审计 demo 双轮运行（121320fe / fbdb6ebd）沉淀。与症状 R 的分工：症状 R 应答「跑太慢/应该毫秒级」的**投诉**（概念纠正+耗时分解）；本节是用户问「这轮符不符合预期、error/返工/消耗能不能优化」时的**主动审计**动作。token 口径/耗时分解用 §3 #8 + 症状 R，不重复；本节只列增量：

1. **block 三分类再下结论**：基础设施性（judge 超时/bad_verdict_json/围栏误伤）-> 修机制；内容质量性（缺结论/非原话/因果链断）-> 该抓，健康返工（§3.5 #8）；判据披露缺口（执行了但留痕形式不符）-> 补 purpose（§3.5 #2）。三类的修复出口完全不同，混着报 = 误诊；别把 judge 超时算成模型遵从问题。
