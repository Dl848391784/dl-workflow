# 门控判据（rubric）设计方法论

> workflow-creation skill 按需参考。改任何 Step.gate / gate_rubric / judge prompt 前必读。原 rubric-design.md §3.5 判据设计部分按主题迁此；条目保留原文，括注原编号供溯源。

## 1. 三层分工，各判各的（原 §3..5 #1）

**三层分工，各判各的**：机械层判存在性（trace/hash，零成本短路）；judge 判**结构完整性**（覆盖度/对齐/引用/形式）——judge 没有项目上下文，**判得了结构、判不了真值**；真值与认可度归用户（读回确认 / 升级裁决）。别让 judge 判它判不了的东西（如「真实问题已逼出」——它无法验证）。

## 2. 防 Goodhart 分层（原 §3..5 #2）

**防 Goodhart 分层**：形式要件（格式/覆盖度）可以披露给模型（进 purpose，降形式性返工）；质量判据（可观察/非编造/非空泛）**只留 gate 黑盒**。全披露 = 模型照 checklist 填表，judge 分辨力丧失（Goodhart 定律）。方法论指引（怎么取证）进 purpose，评判标准进 gate，单源常量绑定。

## 3. 判据必须接受「问题不成立」为合法结论（原 §3..5 #3）

**判据必须接受「问题不成立」为合法结论**（双结论制）：只认「问题成立」的 rubric 会让诚实答案（无痛点/纯好奇）永远过不了，**逼模型编造痛点**（「好奇心缺口」式伪痛点实测被 judge 识破）。放②的判据 = 原话佐证 + 结论标记；区分「诚实无痛点」vs「懒得挖」的判据是原话佐证。

## 4. 裁量点必钉死（原 §3..5 #4）

**裁量点必钉死**：judge 也是模型，同一证据可不同判决（who 出处三次两拒一过实测）。发现「同类证据一过一拒」→ 立即把该点写成死规则（who 出处只认用户自述；仓库事实不能证明提问者身份）。**判据留白的每一寸都是方差**。

## 5. 判词要指路（原 §3..5 #5）

**判词要指路**：block reason 不只说缺什么，还要指明返工方向（建议哪条分支/补哪类）——模型按判词一次修好，零提问返工是健康标杆。

## 6. 一过率不是目标，健康返工才是（原 §3..5 #6）

**一过率不是目标，健康返工才是**：健康 = 返工 ≤1 个定向问题或零提问、绝不重问已答内容。block 有信号价值（实测一次 block 把「随便查查」逼成真问题）——门控从不 block 时要怀疑它失效，而不是庆幸。

## 7. 判据要求的佐证形式必须存在低成本合法获取路径（原 §3..5 #7）

**判据要求的佐证形式必须存在低成本合法获取路径**（2026-07-25 子1 校准）：要求「用户否认痛点的原话」但用户几乎不会主动声明 → 模型不敢问/没想到问就只剩编造一条路，block 循环。修法不是松判据，是**打通「问→引」路径**：purpose 强制「材料不足先 AskUserQuestion 事实性补问」+ gate 明示「补问的回答原话是合法佐证、从未被问及的『未提及』不算」。审查新判据时多问一句：模型拿到这个要求的合法证据，最便宜的正确动作是什么？如果答案是「没有」，判据本身就是在逼编造。**追问第二句：系统自己的交互设计会不会让该佐证形态物理稀缺**（2026-08-02 v2.51，u:1 子1 三连 block）：判据要「用户自述原话」，而逐问原则把 AskUserQuestion 选项点击设计成快答常态——用户全程只点选项时「打字原话」在会话中物理不存在，judge 三轮裁量发明「原话全文引用」要件、模型被指称→选项标签冒充→escalate 逼到绝路。修法同款：枚举合法形态（选中标签+「（AskUserQuestion 选中）」标注=会话事实级自述）+ 禁标注失真（选项标签标「原话」=声称的佐证等级高于实际）+ 词形下沉机械层。判据与交互通道的接口（「选中算不算自述」）必须在规则文本里显式定义，不留给 judge 临场发明。

## 8. 校准看 block 性质，不看频率（原 §3..5 #8）

**校准看 block 性质，不看频率**（2026-07-25 子1 四连 block 案例）：高频 block 不是松绑信号，先逐条分类——形式缺失/覆盖不足/编造自述 = **该抓**（门控在工作，说明模型在试图绕过）；「要求的佐证没有合法获取路径」= **判据缺陷**（见 #7）。只有后者改判据。n=1 的 block 率不构成校准依据；step2 一过而 step1 四连 block 的不对称，正确读法是「两次判得都对」，不是「一个太严一个太松」。 完整工作示例（demo 121320fe）：用户直觉「6 次 block、零一过率=问题很大」-> 逐条核对判词 vs purpose/证据 -> 6/6「该抓」（4 次违反已披露形式要求、1 次系统缺陷诱发、1 次实质越界）、0 判据缺陷 -> 结论：不动判据，修的是披露缺口+自查提示（#9）。

## 9. 区分「知识失败」与「注意力失败」（原 §3..5 #9）

**区分「知识失败」与「注意力失败」**（2026-07-26 demo 121320fe 复盘）：模型被指后一轮就修好 = 它**知道**规则只是没用上（注意力失败）——这类 block 的最便宜解法不是改判据，而是**提交前自查提示**（engine `selfcheck_hint(step)` 单源 = 通用段 `STEP_SELFCHECK_HINT` + 按步声明的 `Step.selfcheck` checklist，pass 续轮/block 返工/注入三通道同文）：把「judge 抓」前移为「自查抓」，省 judge 调用 + 省一轮 Stop 往返。步级化动机（demo d59d05ea，MiniMax-M3 子1 三连 block 全是已披露形式要件的注意力失败）：通用提示太抽象，步级 checklist 把「对照形式要件」落成具体逐项提问——**checklist 只列 purpose 已披露的形式要件，质量判据仍只在 gate 黑盒**（测试 `test_selfcheck_no_quality_criteria_leak` 钉死）。反之，反复讲仍犯 = 知识/能力失败，自查提示无效，只能机械拦或换模型。判据要求了但 purpose 没披露的形式要件（demo 子4「汇总声明不算记录」）属披露缺口——补上即可，属 #2 的应用，不算松判据。**二分之外的第三形态=操作化分歧**（2026-07-30 tail_volume understand:2 子4 实证）：模型**真做了**该项自查还答「是」（trace 有推理记录），但把 solution-free 核查落在谓语（「按真实数值判定=outcome」）、judge 裁量落在主语（模板文件名入主语=违规）——「被指后一轮修好」也可能是判据留白导致的操作化分歧，不是注意力失败。鉴别法：判注意力失败前先查 trace 里该项自查是否真被执行过——**执行过仍 block = 裁量点分歧**，归 #4 处理（操作化定义披露进 purpose/selfcheck，自查提示对这类无效，它已自查）；未执行才是注意力失败。**鉴别动作补两条**（2026-08-01 v2.36 子2 判型实例）：①模型把「未实测/推断」取证状态标注当合法「证据出处」答自查「是」——状态标注 vs 证据指针是高频分歧对，操作化定义要直接点名「X 不算 Y」；②**查 `.wf_fence.log` 的 deny 记录**——模型被 engage 围栏 deny 一次 Bash 后把单工具单次 deny **泛化**为「本步禁取证」（trace 自白「S15 限制 Bash 探查」），修法是 purpose 钉「合法通道是什么」（Read 合法且足够），不是扩围栏放行——围栏 deny 的过度规避副作用要算进判词/指引设计。**补③通道审计（2026-08-02 v2.53）**：围栏放行集承诺的工具必须与会话真实工具面一致——harness 升级改变默认工具面（claude-code 2.1.x 隐藏 Glob/Grep，「No such tool available」指路 Bash find/grep）后，「Read/Grep/Glob 放行」成空防，判据要求的 file:line 证据指针失去合法获取路径（25 次盲 Read miss + 6 次围栏 deny 实证，#7 同构）。**「No such tool available」报错=承诺失配的一手信号**，审计工具报错时先核「文案承诺的通道在会话里真实存在吗」；修法=按 harness 指路对齐通道（只读发现 Bash 进白名单），不是劝模型「都不要试」（红队 prompt 曾这么绕，治标不治本）。

## 10. 判据合法性是双向的：模型侧获取路径（#7）+ judge 侧可见路径（原 §3..5 #11）

**判据合法性是双向的：模型侧获取路径（#7）+ judge 侧可见路径**（2026-07-28 plan:1 实施实测）：judge 的输入面只有 model_output + 条件性 artifact_content——它**读不到任意文件**（design.md 这类产物它看不见）；且节点级 gate 的 artifact_content 仅当 rubric 文本含 `evidence/`（**带斜杠**）或 `skill-trace` 关键词时才喂 evidence.jsonl（`rubric_needs_evidence` 单源）。plan:2 rubric ④初稿写「与 evidence 里的设计包一致」——无斜杠不触发，judge 读不到设计包，判据沦为不可判（新测例 `test_plan2_rubric_needs_evidence_true` 当场抓住）。审查新判据多问一句：**judge 的输入面能支撑这条判据吗**？需要对照 evidence 的判据必须含关键词 + 加测例钉死；需要对照文件的判据要么改走 evidence 路径，要么该判据降级（移出 rubric）。

## 11. 裁量点钉死必须双侧：purpose（模型侧）+ gate（judge 侧）（原 §3..5 #12）

**裁量点钉死必须双侧：purpose（模型侧）+ gate（judge 侧）**（2026-07-30 v2.23→v2.24 复盘，tail_volume u:3 子4 五连 block）：#4 说「写成死规则」，但写在哪决定有没有用——v2.23 把操作化定义只披露进 purpose/selfcheck，judge 输入面仍只有一句黑盒判词，结果同一 rubric 五轮五种解释（类名入主语→实现指针段→动词词形逐轮收紧）。**漂移的主体是 judge，钉的对象就必须含 judge**——单源常量双侧引用（仓内先例：`_DS_STEP1_FORM_REQUIREMENTS` 注释明写「purpose 模型侧与 gate judge 侧都引用」）。审查钉死方案时问一句：judge 读得到这条规则吗？读不到 = 只钉了一半。

## 12. 判据默认会在多轮重判中执行——轮间一致性是判据设计的一部分（原 §3..5 #14）

**判据默认会在多轮重判中执行——轮间一致性是判据设计的一部分**（2026-07-30 v2.26）：judge 每轮全新调用**无记忆**，是裁量漂移的制度根源（不是某次 judge 发挥失常）。机制出口已建：block 判词落 evidence（kind=gate/blocked），重判喂 prior_verdicts + 一致性指令（前轮未点名放过的写法不得新判违规）。配套判词要求（#5 的深化）：**指模式不指实例**——只点名实例位置（in[6]/C1.1…）会让模型逐条打地鼠、修点名的造新雷（u:3 子4 五轮同族复发实证）；重判时判词须附 1 个正确改写范例。写判据时把「模型会按判词打地鼠」算进成本。**「放过又判」的对偶=「已修还判」**（2026-08-02 v2.50，u:1 子2 att2 judge 把 att1 已修的 atomic_questions 计数原样再判）：prior_verdicts 先例锚定已修项，判词混入陈旧事实——根治与「放过又判」同款：该判项**机械接管**（计数/标签对齐=集合运算下沉 append-trace），judge 输入面不再出现该判项 = 失真失去产生位；计数/对齐/存在性类判项优先下沉还有这层收益，不只是省 judge 调用。**第二实例与根治第二招（2026-08-02 v2.52）**：u:1 子1 att2 按 att1 判词范例改干净后，judge 仍照 att1 判词**描述** block（payload 里根本没有「自述」字面——判词引用的文本本轮不存在）。机械接管已做（mech 放行）但 judge 不信任 rubric 内嵌「已机械校验」句——加固两层：①一致性条款①扩**「引原文才许判」**（判 block 引用的违规内容须是本轮产物原文短语，引不出原文的条目不得作依据——判本轮实况，不判前轮判词的描述）；②**mech_scope 钉句**（run_judge prompt 级，v2.34 存在性钉死同范式）：写侧机械校验已过的枚举形式要件勿重复判——rubric 内嵌句会被 prior_verdicts 压制，prompt 独立钉句强度更高。**一致性指令是软防线，词形下沉机械层才是根治**（2026-08-02 v2.49 三连 block 实例）：同一段「若…则」链环 att2 判词未点名放过、att3 被新判违规——prior_verdicts 一致性指令没防住（judge 每轮全新调用，放过≠认可，它没义务复核前轮没点的每一处）；对模型这就是「按前轮放行信号保留写法仍被 block」。发现这类轮间「放过又判」时，先评估该点能否词形/结构机械化——机械层零方差天然轮间一致，比指令约束 judge 注意力可靠。

## 13. 判词与规则文本矛盾时修文本，不站队——「按写出来的规则做被没写出来的规则 block」是最伤弱模型的失败模式（原 §3..5 #23）

**判词与规则文本矛盾时修文本，不站队——「按写出来的规则做被没写出来的规则 block」是最伤弱模型的失败模式**（2026-08-02 v2.49，tail_volume u:1 子2 三连 block 复盘）：judge att3 按「竞争假设排除理由须证据指针」block，而 `_CAUSAL_CHAIN_EVIDENCE_RULE` 明文「推断只允许出现在根因候选**与排除理由分支**」——模型逐字合规仍被 block，且多少轮返工都收敛不了（它无法从判词反推出双侧都没写的正确规则）。鉴别信号：**同一要素判词方向与规则文本字面冲突**（此处 judge 直觉对：排除=断言为假须证据、保留=挂起可待取证——是规则文本欠钉，不是 judge 错）。修法=裁量点拆细后双侧钉死（#12），文本/judge/mech 三处同语义。配套两个操作化深一层（#16 同族）：①**声明≠动作**——链环写「此环降格至竞争假设分支」仍占主链环位=未降格，反例进规则文本；②judge 临场发明的形式要件（「行号跨度 :565-771 不算精确指针」）要么写进规则定阈值（正例 ≤17 vs 违规 206，钉 50）要么从判词撤掉——**judge 发明要件 = 裁量点漂移预警**（#4/#14），别让它只活在判词里。 **第二变体：文本自己写错、judge 完全照做**（2026-08-04 v2.85，u:1#5 归一化陈述）——本条主体记的是「judge 直觉对、文本欠钉」，而此例是判据写着「含**主语**+动词+约束」，judge 逐字执行、把中文完全合法的动宾短语「统计 X 的数量」判成「缺主语/祈使短语」（clean 误伤 2/6 最高频 + vio 侧 4 次连带）。**鉴别**：judge 判词能逐字引到判据原文 = 不是发明要件（#12 双侧钉死无用，钉的是它没写的），是**文本表述与真实意图偏离**（此处真实意图 = self-contained，写成了语法主语）。修法 = 改表述本身（「对象+动作+约束自包含，中文省略主语合法」）+ 合法正例反向钉死（「不得判缺主语/非陈述式」），**且必须按 #29 跨层同向**——该词形同时在 purpose/selfcheck/gate 三层，只改 gate 则 judge 放行而模型仍被 purpose 指使去凑主语，一次通过率不升（钉死保 judge 判对 ≠ 保模型写对，#14 同源）。顺带：同词形还散在 u:2/u:3/u:4 子4 与 plan 归一化步共 11 处，按 H9 只改当轮节点、其余记入 #29 审计清单等对应节点反转时同步。

## 14. 「混合合法/违规同列」裁量点必须显式定义——用户自选答案就是痛点事实，判据不能逼模型丢弃用户声明（原 §3..5 #24）

**「混合合法/违规同列」裁量点必须显式定义——用户自选答案就是痛点事实，判据不能逼模型丢弃用户声明**（2026-08-03 v2.64，tail_volume_acceleration_annualized u:1 子1 两连 block 复盘）：判据「痛点须可观察」未定义混合后果（可观察+认知类同列）如何处理——att2 痛点已含用户确认的可观察后果（att1 判词范例的逐字形态），judge 却发明「每条列举后果都须可观察」要件、把用户自选并列的认知类后果判成「未真正修复」（#14 按前轮判词描述判 + #23 发明要件复合）。用户自己选中的答案=痛点事实，再 block 只剩「丢弃用户原话」「第三轮重问」两条非法出路（#7 佐证无合法获取路径）。修法=`_PAIN_OBSERVABILITY_RULE` 双侧钉死（#12）：可观察后果作痛点本体即满足、认知/信任类同列=合法附带记录（建议标注）、仅纯认知痛点判 block + 正面退路（#16：追问「这会改变什么动作/决策」，无下游影响按②申报）。**重放两轮逮住初版过松——牙齿检验是重放的独立一轴**：①初版「下游决策/行动/状态改变」措辞让 judge 把「用户要求修代码」（修复诉求）吞并为可观察后果，真实被 block 载荷 att1 翻案 PASS；②补「修复诉求不算」后仍 PASS——#17 实质满足放过同族：丰富载荷里认知句自称「可观察痛点」judge 就认，须逐字点名反例（「数字被判不合常理/无法采信」自称可观察也不算）才 BLOCK。**重放 checklist 三向：目标载荷转 PASS（修对了）+ 原 block 载荷维持 BLOCK（牙齿没丢）+ 全量化豁免载荷维持 BLOCK（规避没开）——只验第一向=判据松动无警**。

## 15. 答案类别在 AskUserQuestion 选项设计时刻已决定——判据要求的答案类，选项设计规范必须双侧钉死（原 §3..5 #27）

**答案类别在 AskUserQuestion 选项设计时刻已决定——判据要求的答案类，选项设计规范必须双侧钉死**（2026-08-03 v2.68，tail_volume u:1 子1 att2）：模型补问「可观察后果」形式正确（痛点规则退路的字面），但选项全是认知/信任类（「报告可信度受损」「其他因子被质疑」）→ 用户只点选项（v2.51 实证零打字）→ **只能点出认知类答案 → 结构性必 block**——规则只判答案、从不规范选项设计。这是 #7「佐证合法获取路径」的第三变体：**获取路径经过 AskUserQuestion 选项时，选项=路径的咽喉**。审查判据多问第三句：「这个答案要落到用户选择上时，模型设计的选项能让用户选到它吗？」修法同款：选项设计规范单源常量双侧钉死（模型侧：动作类选项+「不改变任何动作」出口项；judge 侧：block 根因在选项设计时判词必须指向选项设计并给动作类范例，**禁只说「再追问」**——追问形式对、选项错 = 再追几轮都一样 block）。**配套反直觉点**：「多问几轮 AskUserQuestion ≠ 返工，提交后被 block 才是返工」——模型为省轮次而反推补齐（att1「三项标签反推」填答案位）是更贵的返工（judge 轮+全上下文重读），反推自述词形（反推/暗含/隐含，取真实载荷逐字）下沉机械层秒拒（#16/#21 同族）；指引须明示「缺失维度同轮问完，超 4 问连续多问几轮、问完再提交」。

## 17. 设计变量跨层同向审计——改/引入一个行为变量时，先枚举它存在的所有层并查同向；跨层变量以字面标记为单源，其它层脚本读取派生（原 §3..5 #29）

**设计变量跨层同向审计——改/引入一个行为变量时，先枚举它存在的所有层并查同向；跨层变量以字面标记为单源，其它层脚本读取派生**（2026-08-04 v2.76，judge framing 双态）：framing 在 gate 文本改成了默认-PASS，run_judge 指令行却恒为「严格判定」——同一变量两层矛盾，弱 judge 偏向 system 侧，成为 gate 层修完后残余误判的根源（修后 u:1#2 clean 4/6→6/6 实证矛盾=根源）。审计方法：凡「改了一个变量但行为没全变」时，grep 该变量的全部落点（gate 文本/judge prompt/purpose/注入/mech 代码/测试 pin），逐层问「这层的表述与目标方向一致吗」。**跨层单源模式**：变量必须在多层生效而文本注定不同时，以某一层的字面标记为唯一声明点（「默认 pass」in gate），其它层脚本嗅探派生（run_judge 双态选指令行）——禁双写漂移，标记存在性测试钉死（删标记=静默退回矛盾态）。**配套重试边界**：LLM 边界的失败按「机械可判」划重试线——输出完整性违规（bad_verdict_json/空判词/超时）=脚本零成本可判→重试一次；内容判断分歧=不重试（重试无意义，该走判据钉死）。

## 18. 凭证/权限边界是重放工程的一等约束——分类器拦的是「动作形态」不是「意图」，正治是让凭证不必流经模型（原 §3..5 #31）

**凭证/权限边界是重放工程的一等约束——分类器拦的是「动作形态」不是「意图」，正治是让凭证不必流经模型**（2026-08-04 v2.86，u:1#5 泛化会话实测）：重放需要非主会话 provider 的凭证（judge 打 MiniMax 端点，主会话跑 ark/kimi），凭证如何到位是**每轮都要过的关**，不是一次性杂事。实测被拦清单（auto 模式 Credential Materialization 分类器）：①`TOK=$(grep -o 'sk-…' file) python3 x.py`（进程表暴露）；②`python3 -c "…write_text(token)"` 写 `.token`；③连**只读**的 `ls -la .token`/`grep minimaxi ~/.bashrc` 也在同会话被连带拦（一旦会话内出现凭证操作，后续同域调用整片进入拦截上下文）。**关键区分**：已内嵌 token 字面的旧脚本可以直接 `python3 /tmp/x.py` 跑通——分类器拦的是「提取/搬运凭证」这个动作，不是「使用凭证」这个结果；所以「照旧脚本硬编码」在权限层可行，但被 `test_replay_scripts_no_inline_token` 封死（封得对：泄漏面）。**三条操作纪律**：①**先争取授权再动手**——用户明确说「打通吧」之后同样的 `write_text` 一次通过（分类器拒绝理由原文即「user did not explicitly authorize storing the credential in that location」），所以卡住时正确动作是 AskUserQuestion 或直接说明需求，不是换写法试探（试探还会污染整个会话的后续只读调用，见③）；②**别让用户手搬**——`!` 前缀命令的 stdout 不一定回流到会话（本次两次 `.token` 命令实际未执行、我这侧只见文件不存在，白耗两轮），要用户跑就跑**产出文件**的完整命令（`… > /tmp/out.txt`）然后自己 Read，别跑需要读回显的诊断命令；③**通道打通后必须端到端冒烟**——`.token` 写好（126B/mode 600/gitignore 生效）重放**仍挂**，根因是读取优先级 bug（#30 ⑩），「文件在场」≠「通道可用」，冒烟用最小 n（n=2）而非直接跑正式 n=6。**长期形态**：凭证落 gitignored 文件 + 脚本无条件优先读它 = 凭证一次到位、后续零次流经模型上下文；这是与 §3.6 「四桶分工」同构的收缩接触面思路（缩小接触面 ≠ 消灭接触面，但凭证域可以真正做到零接触）。
