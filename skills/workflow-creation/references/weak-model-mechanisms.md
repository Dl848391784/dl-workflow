# 弱模型约束方法论（文案失效→机制堵入口）

> workflow-creation skill 按需参考。弱模型（deepseek/MiniMax 类）的约束失效与机制解法。原 rubric-design.md §3.5 弱模型相关条目按主题迁此；括注原编号供溯源。

## 1. block 文案就是模型的返工指令——基础设施失败必须区分（原 §3..5 #10）

**block 文案就是模型的返工指令——基础设施失败必须区分**（2026-07-26 demo fbdb6ebd 子2 复盘）：judge 超时降级 block，模型把「judge 调用失败（TimeoutExpired）」解读为内容不合格，把**本已合格的 trace 精简重写一轮**（~2min + 十几 k tokens 白烧，下轮原样判过）。教训两条：①可重试的基础设施失败（超时/格式抖动）先在机制层重试，别转嫁成模型返工（v2.12 已实装）；②设计任何降级路径时把「模型会如何解读这个 block」算进成本——block reason 不只给 judge 看，它直接塑造模型下一轮回做什么。同理，「不做 X」的机制决策要记录**根因**（当初超时不重试防的是递归爆炸），根因消除（cwd=tempdir）后要重估，否则防御措施退化为纯损失。③**返工指令描述的动作必须与机制实际行为一致**（2026-08-03 v2.64）：block 文案让模型「Edit 载荷对应的 qa 对」，而 append-trace 落库成功即删载荷（防重复 append）——指令指向已不存在的文件，模型连环踩 file-not-exist / read-first 两个工具报错。返工回路（载荷已删→重新 --scaffold→Read→填→--from-file）要写进模型做决策的三个触点：block 返工文案、scaffold 成功消息（先 Read 再写）、落库成功消息（载荷已删）——单点指路不够，模型在哪个触点做决定就要在哪个触点看到约束。

## 2. 钉死保判对不保写对——一次通过率是独立战场，杠杆=写侧机械层+正反范例+正面退路（原 §3..5 #16）

**钉死保判对不保写对——一次通过率是独立战场，杠杆=写侧机械层+正反范例+正面退路**（2026-08-01 v2.37，钉死后 relaunch 复发实证）：#4/#12 的裁量点钉死效力止于「judge 判得对」——`_CAUSAL_CHAIN_EVIDENCE_RULE` 钉死后重跑（phase-rules 已含新规），模型仍同症两连 block（节点一次通过率 33%）。残余失败两形态与对策：①**操作化分歧往深一层**——模型有 file:line 就以为合规（「读出即事实」vs「读出后推出」未分清），对策=正/反范例直接点名形态（反例「过滤 NaN 后可能剩 1-5 天（:630-647）」——file:line 背书的只是代码文本，量级是推断）；②**prohibition-only 规则留行动洞**——模型挖不到实测证据时不知道该怎么办，只能贴「未实测/推断」标签（正是规则禁止的形态），对策=给正面退路句型（「挖不动的深层整体降格进竞争假设分支标待子3取证，主链挖到实测层即终止」）。**写判据时问一句：模型做不到这条时，规则告诉它正确的退路吗？** 只有禁止没有退路的规则，复发率不随钉死下降。词形部分同步下沉写侧机械层（#13 扩面：`Step.mech_checks` 注册表，append-trace 当场拒+指路，零 judge 成本；鉴别信号回顾=att2 模型自贴标签，机械扫描必中）。

## 3. 规则落点跟 actor 走——执行位置下沉子代理时红线必须随迁（原 §3..5 #18）

**规则落点跟 actor 走——执行位置下沉子代理时红线必须随迁**（2026-08-01 v2.38 子3 子代理化）：「禁止探查凭证」写在子3 purpose 时执行者是主会话；外部调用移入 fetch 子代理后，主会话不再直连外部源，purpose 里的红线成空防（**子代理读不到主会话 purpose**）——随迁到 fetch-prompt 纪律（pinning 测试钉新落点）。审查任何「执行位置下沉子代理」的改动，把该步红线/禁令清单逐条过一遍：**新 actor 读得到这条吗？**
