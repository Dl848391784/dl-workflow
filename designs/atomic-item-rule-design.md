# 「复合句」裁量点钉死（_ATOMIC_ITEM_RULE）设计

> 2026-07-31，tail_volume_acceleration_annualized plan:1/plan:2 运行审计驱动。
> 变更 = 判据钉死杠杆（弱模型优先第一杠杆），不动 schema/流程。

## 问题

tail_volume 工作流（2026-07-29 晚）连续两个归一化步各三连 block、均用户强制放行收场：

- **plan:1 子5（归一化设计陈述）**：judge 三次判「非单句/复合句」（att1 称条目含「数十个『。』断句」——重放真实 trace，条目 ≤1 个「。」，判词失真；att2 判「括号、加号、斜杠并列谓词」——即八字段键值枚举形态本身）。
- **plan:2 子4（归一化执行步骤）**：judge 三次判「复合句」（U1 = 写失败测试 + 最小实现 + 验证 + commit「四步串联」）。

**根因 = 判据自相矛盾**：gate 形式要件同时要求「八字段/五字段齐备」（同项携带）与「每项 ≤1 句」——字段全带必产出键值枚举/括号形态，judge 按词形（「+」「然后」「以及」、括号、多项罗列）把枚举形态判成复合句，合法产出无通过路径，只能升级用户裁决。用户两次均选「接受当前原状，强制放行」= 用户认可产出形态、不认可判词。

**为什么不是机械预检**（原审计建议被否）：重放对比被 block 条目（'+' 4~17 个）与同 workflow 通过的 ProblemContext 子5 条目（'+' 0~3 个）——分隔 margin=1，阈值法是第一性原理禁止的调参数式修复；且通过 trace 的名词枚举用法（"backtest_results + 4 处模板 + 分级带"）与被 block 的动词串联词形相同，机械规则分不开。

## 变更

新增单源常量 `_ATOMIC_ITEM_RULE`（dl_flow_nodes.py），与 `_SCOPE_VERB_RULE` 同构（按指向/独立性判，不按词形判）：

> 原子性按独立性判、不按词形判：字段键值枚举（「字段名=值」以「；」「+」「、」或括号携带）与一项的内含流程 = 结构化携带，不算复合；复合句 = 一项合并 ≥2 个可独立成立的项（可分别拍板/分别提交）。

双侧引用（v2.24 先例：purpose/selfcheck 模型侧 + gate judge 侧）：

- **DesignSolution 子5**：每项 = 1 个可独立拍板的设计决策；八字段键值枚举随项携带不算复合。
- **TaskBreakdown 子4**：每项 = 1 个可独立验证/提交的交付物；TDD 微循环（失败测试→最小实现→验证→提交）= 交付物内含流程，不算复合。

不适用面：ProblemContext 子5 等痛点陈述步的「和/以及/同时」多痛点判据不动（无字段携带矛盾）。

## 预期收益（按审计实测口径）

每个归一化步省 ~3 轮 judge（41.9k input / $0.44 / 含一次 120s API 挂死）+ 3 轮模型返工（~10min 墙钟），且消除「判据无通过路径 → 强制放行」的裁决税。
