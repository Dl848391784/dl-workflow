## 2. 误伤模式聚类（clean 4 轮误判判词逐字）

1. **发明「矩阵须表格/M×N 形式」要件**（clean#1/#4/#6，主因 3/4）--判据「逐项列出」
   被曲解为须以表格/M×N 矩阵形式呈现。判词原文：「未以矩阵形式逐项列出目标行×问题列
   的对应关系（如表格/M×N项），形式不满足」「仅给'P1×G1=承接'一行汇总，未逐项展开」。
   实际=backward+forward 各以具体问题/目标点名列出即逐项（prose 即可）。
2. **发明「主语操作性核对」要件**（clean#4）--判据「主语无实现侧名词即 outcome-level」
   被曲解为须显式说明「主语为何不含模板」。判词原文：「本轮G1未做主语操作性核对
   （仅声明outcome-level，未说明主语为何不含模...）」。
3. **发明「outcome 非同义反复须显式验证」要件**（clean#1）--判词原文：「缺方案剥离后
   outcome 非同义反复验证」。实际=outcome 指向用户可见状态即非同义反复，不要求显式验证声明。
4. **artifact 两行混淆**（clean#3）--judge 把子1（sub_step==1）误读为 sub_step==2、
   发明「取最后一条为判对象」要件。判词原文：「你提交了 2 条 skill-trace，sub_step 均为 2，
   需取最后一条为判对象」。此条已被 v2.78/v2.79 全局 engine 注覆盖（前序=一致性对照基准），
   从严 framing 下 judge 仍发明。

全部误伤=从严 framing 下 judge 对「逐项列出」单向模式匹配过度适用 + 发明要件，
与 u:1#1-#4 同根因。

## 3. 设计决策

### 3.1 framing 反转（主杠杆）
「质量判据（从严裁量）」->「默认 pass--仅当以下成立才判 block」+ 方框化 3 条真值判据：
1. 同义反复（剥离后 outcome=做X为了能做X）
2. 矩阵放水（明显无关联的问题-目标硬连/脑补目标挂到无关问题）
3. 汇总声明无逐项矩阵（「全部对齐」式汇总不点名任何问题-目标对应）

### 3.2 每条方框判据近端双侧钉死（词形取 §2 误判判词逐字）
- 形式要件「逐项列出」：backward（每个目标≥1 问题回溯）+ forward（每个存活问题有承接
  目标或显式搁置+理由）各以**具体问题/目标点名**列出即合规，**不要求表格/M×N 形式**，
  prose 逐项即算逐项列出（治聚类 1）；点名了具体问题×目标对应即非「全部对齐」式汇总
  （治 vio3 边界）。
- 形式要件「方案剥离」：主语无实现侧名词（模板文件名/类名/函数名/管线名等）即 outcome-level
  合规，**不得发明「主语操作性核对/说明主语为何不含」要件**（治聚类 2）。
- 一、同义反复：outcome 复述方案动作本身（「做X为了能做X」、无真实状态转换）判 block；
  outcome 指向用户可见状态/数字/信号即非同义反复，**不要求显式「非同义反复验证」声明**
  （治聚类 3）。
- 二、矩阵放水：明显无关联的问题-目标硬连（脑补目标挂到无关问题上）判 block；
  目标与问题有承接逻辑即非放水，不要求逐行展开明细。
- 三、汇总声明无逐项矩阵：「全部对齐」式汇总（不点名任何具体问题-目标对应）判 block；
  点名了具体问题×目标对应即非汇总。
- 前序记录：artifact=子1+子2 拼合是生产常态（子1 goal_candidates 是对齐判对象=锚点），
  前序子1 trace 的存在与组成不作 block 依据（治聚类 4，与 v2.78/v2.79 engine 注同向）。
- 【合法正例】段：prose 逐项即逐项（不要求表格）/主语无实现侧名词即 outcome-level
  （不要求操作性核对）/前序子1 trace 是锚点非判对象（治聚类 1/2/4）。
- 「方框以外一律不判。」

### 3.3 不下沉 mech

### 关键现象与新教训（超出 u:1#1-#4 经验）

1. **压跷跷板三例同节点**（v1↔v2↔v3）：本节点三方框判据两两压跷跷板--
   - v1 严 form 保 vio2(6/6) 但 vio3 漏(4/6)；
   - v2 放宽 form+显式方框三 保 vio3(5/6) 但 vio2 崩(3/6)；
   - v3(v1 form+v2 方框三) 保 vio2/vio3 但 clean#3 推理底。
   根因：vio2（矩阵放水=语义）+ vio3（汇总无矩阵=形式边界）+ clean（逐项 prose）
   共享「逐项列出」判据，弱 judge 对「逐项 vs 汇总」「相关 vs 无关联」判定不稳。
   **解=不在 form 严格度上跷跷板，而按 #30 ⑫分治**：vio3 用显式方框三（穷举泛指
   词形「全部对齐/所有目标均已对齐/每个存活问题都有目标承接」），vio2 用 obviously-
   unrelated 载荷（G2 与 P1 零概念重叠让 judge 稳判无关联），clean 用「forward 简写
   点名标识即够」退路。三方框各自钉死、不共用一个 form 旋钮。

2. **vio2 载荷设计：脑补目标须与问题零概念重叠**（v3→v4）：v3 G2「降低因子计算管线
   运行耗时」与 P1「统计正IC因子数量」共享「因子/管线」概念面，弱 judge 4/6 判不出
   无关联（读成同域相关）。v4 改 G2「掌握代码仓库的 README 文档结构现状」（与 IC 统计
   零重叠、outcome-level 无方案名词混淆）-> vio2 5/6→6/6。**教训补 #30 ②**：构造
   矩阵放水 vio 时，脑补目标须与存活问题**零概念重叠**（不同关注点），共享域词的
   近义目标会让弱 judge 把「无承接」读成「同域相关」漏判。

3. **「决定X=决策用途」钉死治 clean 推理底**（v4→v5）：clean G1「得到正IC因子数量，
   用它决定筛选门槛」--judge 非确定性地把「决定筛选门槛」读成方案动作、「筛选门槛」
   读成实现侧名词（v3 pass / v4 block，纯 judge 方差）。根因=「决定」动词的
   outcome(决策) vs 方案(动作) 二义性。v5 加「『用于决定 X』『以 X 决策』=决策用途=
   outcome-level，非方案动作」双侧钉死 -> clean 稳定 6/6。**这是可钉死的 framing
   二义性、非打地鼠无底洞**（#28 推理底鉴别：判词方向与规则文本冲突=可钉死；
   自相矛盾判词/发明无底洞要件=停止钉死）。
