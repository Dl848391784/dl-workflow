### 1.1 误伤模式聚类（clean 6 轮判词逐字）

1. **dry-run 留痕形式要件**（4/6 主簇）：`which python3`/`which pytest` 被判「只验
   解释器/工具存在，未对判据命令本身 `python3 -c "from paths import
   CATEGORY_SUMMARY_RESULT"` / `pytest tests/... -x` 做实际 dry-run」——clean 原用
   which/collect-only 作判据可执行性留痕，judge 读「实际 dry-run」=判据命令本体。
   **载荷侧正治（⑦ 先查载荷缺陷）**：clean 改为判据命令本身 dry-run（CP1 实跑判据
   命令退出码 0；CP2 因测试文件 TDD 先行属假设，标假设）；gate 侧钉「判据命令本身
   dry-run（命令+退出码/收集输出概述）即合规，不索结果对错/退出码原文」。
2. **CP2 测试文件假设归位**（2/6）：CP2 判据依赖测试文件 tests/test_summary_
   categories.py 未生成（TDD 先行），judge 要求该项标「假设」而非「已验证」——
   clean 原全标已验证+单独假设项，judge 读成矛盾。**载荷侧正治**：CP2 判据可执行性
   直接标假设（附置信度+影响）；gate 侧钉「判据依赖未生成物件时可执行性标假设
   即合规」。
3. **无证伪项被索要**（2/6）：clean 全对象已验证为主+一项假设，judge 索「证伪」
   标注与「无证伪声明」——gate 侧钉「无证伪项不须声明『无证伪』；三态混合（已验证
   为主+假设）即合规；三态按对象标注不须逐类拆标」。
4. **交集实算粒度**（1/6）：judge 索「逐 worker 清单单独实算」，clean 只对 L2 组
   做了交集实算——gate 侧钉「并行组交集实算一次即合规，不要求逐 worker 清单单独
   实算；串行组/无并行组声明不适用即合规」。
5. **sub_step==3 记录识别幻觉**（1/6）：judge 称「sub_step==3 记录内容实为执行计划
   产物非锚点核验」——子1/子2/子3 三条 trace 拼合下的识别噪声，属 judge 方差，
   反转后 default-PASS 下预期消失，不计入钉死位。

## 2. 反转后的判据设计（默认-PASS framing）

形式要件段更新（逐对象留痕+三态按对象标注的澄清，去「从严」措辞）。五方框 = 原
四条从严判据逐条双侧化 + 同族第五方框（漏对象核验）：

- 方框一（声称可执行/存在/绑定无留痕=编造）：双侧钉「判据命令本身 dry-run（命令+
  退出码/收集输出概述）即合规，不索结果对错/退出码原文/完整回显」+「命令存在性检查
  （which/--version/--help）亦属留痕、不因未跑判据命令本体而判违规」+「判据依赖未
  生成物件（如 TDD 先行测试文件）时该项标『假设』即合规，不索该物件 dry-run」
  （聚类 1/2 双侧）。
- 方框二（互斥面交集核验无实算输出=没真核验）：双侧钉「并行组各 worker 改动文件
  清单集合交集实算（命令+输出）即合规，不要求逐 worker 清单单独实算、不索实算脚本
  原文」+「纯串行 DAG 声明『无并行组、互斥面不适用』即合规」（聚类 4）。
- 方框三（全对象无差别「已验证」=没真核验）：双侧钉「三态混合（已验证为主+个别假设/
  证伪）即合规」+「无证伪项不须声明『无证伪』——不得以『没有假设/证伪项』本身判
  block」+「三态按对象标注即合规，不须逐类拆标」（聚类 3）。
- 方框四（假设项缺置信度或影响）：mech-托声明（plan:2#3 box 四同款）——已由
  assumption_completeness_trace 机械校验、不得以此 block；残留判面=假设标签形以外
  的假设提及是否明显矛盾。
- 方框五（漏对象核验）：某核验对象四类之一缺留痕，被「随 X 覆盖/同 X 已验证」代过
  判 block；合法形态=逐对象四类留痕即合规，某类不适用附声明即合规。
- 【命题性质】段（㉚①）：三态是标注不是裁决，不得以「标假设未标已验证/未裁决假设
  接受」为由 block；dry-run 验命令存在且可运行、不验结果对错——不得以「未验判据命令
  结果对错/命令 execute 期才真跑」为由 block；交集实算结果不核真（不重算分组正确性）。
- 【判材边界】段（㉚②）：四源文件 + codegraph db/文件系统真值结构性不可见——只判
  trace 内留痕在场与自洽，不核「文件/命令/锚点/工具是否真存在真能跑」；子1/子2 自身
  方案内容/假设不重核。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **同族节点复用判据时「载荷先修再钉」**：plan:2#3 与 plan:4#3 同为锚点核验节点，
   但四类核验内容不同→clean 载荷必须按本节点真实语义构造（dry-run=判据命令本体、
   CP2 测试文件假设归位），不能直接抄兄弟 replay 载荷形态。⑦ 先查载荷缺陷再查 gate
   在同族复用时是第一道，不是补漏。
2. **「实际 dry-run」的载荷-判据语义对齐**：purpose 写「判据的命令实际 dry-run」，
   judge 读成判据命令本体执行；clean 用 which/collect-only 代理=载荷侧不满足字面。
   载荷侧满足字面 + gate 侧钉「命令存在性检查亦属留痕」双侧缺一不可。注意两侧是
   跷跷板：v1 给 which（被嫌非判据本体）→ v2 纯假设（被嫌无留痕）→ v3 假设附
   `pytest --version` 存在性留痕（双侧同满足）。
3. **「不索 X」类合法形态会被反读成「给了 X=违规」**（㉓ 变体再证）：v3 钉「验证手段
   绑定=绑定声明即合规，不索出处」→ 落地轮 judge 反读成「模型给了 Read 出处=非声明
   形态=违规」。修法=双侧化到「任一或兼有均合规」：声明与出处并列双形式，不得以
   『给了声明而没给出处』『给了出处而没给声明』『出处非行级』为由 block。凡「不索 X」
   的合法形态，必须同时钉「给了 X 不违规」。
4. **n=6 单轮读数在弱 judge 高方差节点不可靠**：同 gate 跨轮 clean 3-6/6、vio2
   3-6/6 摆动（橡皮图章空 reason PASS 随机命中不同载荷），n=10 才出稳定带（clean
   9/10、vio 8-10/10）。判据达标判定应看 n≥10 的稳定带，n=6 只作粗筛（方向对错）。
   橡皮图章空 reason PASS 是 default-PASS 弱 judge 的固有现象（plan:2#3 vio4 同款），
   词形可判项下沉 mech（本节点=假设完整性）是根治；其余语义项接受 ≥5/6 阈值的残余
   橡皮图章。
