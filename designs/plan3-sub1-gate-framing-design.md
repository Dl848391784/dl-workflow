## 2. 反转后的判据设计（默认-PASS framing）

结构：形式要件（保留 _CTS_STEP1_FORM_REQUIREMENTS）+ 默认 pass 声明 + **三方框**
（复用 plan:2#1 判据一(a/b)/二/三结构）+ 【判材边界】段 + 【合法正例】段。

- **方框一·需求来源自证不足（编造/静默新增）**：(a) 全清单裸=编造（「按 plan.md
  常规结构可知…按常规路径可查」类凭印象）；(b) 个别条目裸且未标新增候选=静默
  新增（「新增候选：无」声明下清单含无出处无原文引用的新增需求条目，如「跑
  fresh 检查验证 PRICE_VOLUME 全量落库」）。合法形态=任务 ID+plan.md 行号 /
  『原文』引用任一在场即合规。
- **方框二·改写失真（语义偏移）**：自述措辞 vs 引用的原文『…』三维对照（操作
  对象/性质/产出物任一明显变化判 block）；合法形态=忠实提取/适度压缩/适度具体化
  （原文「在既有聚合统计函数内…」自述点明函数名「`_aggregate_positive_ic` 内…」
  = 具体化非语义冲突——v3 迭代加的合法形态，治 v3 clean 5/6 漏网误伤）。
- **方框三·需求原文未引用**：v1 重放后下沉 need_quote_trace mech（§3）；
  judge 侧残留判面=无代码符号形的需求条目是否附出处行号或『』引用。

【判材边界】（plan:3#1 特有判面）：input=plan.md 主仓 .md 文件 + plan:2 前步
trace 均结构性不可见；**操作类型分类的语义正确性属子2 能力盘点判面**——本步
只判「操作类型标注在场」，不得复核分类正确性/归属口径/标注粒度（「.md 数据读取」
vs「数据读取[parquet 等]」粒度差异不判）；**操作类型清单=「每任务标注其实际
涉及的操作类型」，不是「六类全谱系逐项有/无标注」**——plan.md 没有的类型不要求
显式「无」标注，不得以「缺测试执行类型标注/六类未全覆盖/其余类型未显式无」为由
block（治聚类 1/3，本节点特有——plan:2#1 的要素清单无枚举完备性歧义）。

【合法正例】（各聚类合法形态落位）：任务 ID+行号+原文片段引用；数据读取需求引用
断点验证段原文是合法出处（需求出处=plan.md 中承载该需求的段落，不限于同名字段）；
「.md 数据读取」粒度标注合规；清单只含代码改动/数据读取两类（plan.md 实际涉及的
类型）合规。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **同构保真基线节点的判据可整体复用，只需换输入锚**：plan:3#1 与 plan:2#1
   判面同构度 ~90%（四 vio 一一对应、判材边界同型、mech 正则直接复用）——
   此类「从 X.md 提取清单」节点的反转成本主要是**载荷保真度设计**与**特有判面
   差异**（本例=操作类型枚举完备性歧义），不是判据重新设计。选下个节点时先问
   「与已反转节点同构吗」可预估一轮达标概率。
2. **形式要件的枚举参照会被 judge 反读成逐项必填**（㉓ 第四变体）：「操作类型
   （代码改动/测试执行/长 pipeline/外部检索/数据读取/子代理扇出/文档装配）」
   是模型侧标注参照，judge 读成「六类全谱系逐项有/无标注」判据——**枚举型形式
   要件的【判材边界】必须钉「清单=实际涉及类型非全谱系，未涉及类型不要求显式
   无标注」**。这是枚举完备性歧义族的首个实例（plan:2#1 的三清单无枚举、无此
   歧义）。
3. **mech 委托声明引入的新误伤模式=「具体化=失真」**：judge 把自述中**点明原文
   未点名的具体符号**（函数名/文件名）读成改写失真——合法形态族须包含「适度
   具体化」（原文「在既有聚合统计函数内…」→自述「`_aggregate_positive_ic` 内…」
   合规）。保真判据的「失真」与「具体化」词形邻近，须显式双侧钉死。
4. **vio3 改写失真的 block 面必须给载荷同形逐字实例**（㉑ 第二实例）：抽象
   「自述 vs 原文冲突」标准 3/6，逐字违规实例前置后 6/6——改写失真/语义冲突类
   判据的 block 面设计模式=「抽象三维对照 + 载荷同形逐字实例」双件套。
