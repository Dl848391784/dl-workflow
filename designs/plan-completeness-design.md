# plan 完备性（执行零求证）设计

> 日期：2026-09-10 ｜ 状态：用户 goal 授权实施（/goal：用 ac-deepseek1 实跑测试工作流验证到达标）｜ 分支：feat/plan-completeness
> 起源：early_summer_screener 施工复盘——v1_text plan 判据本体钉死但「数据消费契约」缺位，执行期被迫实读 3 处（市值文件结构/单位换算、RealDataLoader 构造与失败语义、「年内」操作化）。用户定标准：**plan 完备 = 执行者除了写代码和跑测试，不需要打开任何其他文件求证**。

## 1. 标准定义

事实类问题（数据在哪/什么格式/什么单位/怎么读/先例什么样）必须在 p 阶段产物里是**定论**。执行期合理动作只剩两类：①按规格落码；②处理规格无法预知的实现层意外（如 np.bool_ 坑——plan 不可预知，属合法执行发现，不算欠债）。

## 2. 改动点（4 处，对齐同一概念「数据契约」）

### ① plan:2 子3 purpose（生产侧，dl_flow_nodes.py ~3654）

interface 字段定义从「Consumes+Produces 精确签名」升级为：

> 签名 + **数据契约**——步骤消费数据/文件/API/缓存时必给五要素：格式样本（文件结构/记录示例）、单位与换算、时序语义（排序/最新值取法）、失败语义（None 还是异常/缺记录形态）、读取先例（file:line）。纯函数接口显式声明「纯代码接口」即豁免契约要素。

### ② append-trace 机械校验（dl_flow_checks.py）

interface 条目含**数据消费信号词**（读/数据/json/parquet/gzip/DataFrame/API/缓存/文件/源码）时，须同时含 ≥2 个**契约词**（单位/格式/结构/失败语义/示例/先例）或含「纯代码接口」豁免声明——否则当场拒（与 fields 五键非空同款拒法；钉死非裁量，弱模型友好）。

### ③ plan:2 子3 gate rubric（judge 侧，dl_flow_nodes.py ~3787 判据区）

- 判据补条款：interface 数据契约与 step 材料不符（格式/单位写错）或五要素缺漏判 block——judge 判内容质量面
- 判材边界补：豁免形态已由机械校验，不得仅以「签名不够详细/契约格式不合我意」为由 block（默认-PASS 方框，防 thrash）

### ④ u:1#4 双向取证 purpose（取证产出侧）

数据类锚点标准从「存在性锚点」升「**可消费锚点**」——凡标注「供给面/先例」的条目必须带读取形态（结构/单位/失败语义/读取先例行号），使 plan:1/2 消费时无需再实读源文件。

## 4. 边界与取舍

- **不追溯历史实例**：只影响新工作流（旧 plan.md 不合格式不补）
- **信号/契约词清单第一版保守**：误拦成本 > 漏拦成本（豁免声明随时可写；宁可放过不可 thrash——judge-framing 教训）
- **「年内」类语义裁决不进机械层**：属内容判据（judge 判「量化口径未操作化」），机械层只查契约要素存在性
