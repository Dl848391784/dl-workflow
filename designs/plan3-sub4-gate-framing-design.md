## 2. 反转后的判据设计（默认-PASS framing）

结构：形式要件（**不再回引常量**——本节点无 `_CTS_STEP4_FORM_REQUIREMENTS` 单源常量，
form 直接内联并按 §1.1 操作化）+ 默认 pass 声明 + **四方框**（每条 block 面+legal 面
近端双侧钉死，词形取 §1.1 误判判词逐字）+【判材边界】段 +【合法正例】段 + 条款引用要求。

- **方框一·声称可用无出处**（vio1）：block 面=声称可用却无任何出处留痕，穷举两违规
  形态（口头声称「已装可用/版本没问题/db 也在」无命令 / 四类整段概括复述无绑定特定
  命令）；legal 面=命令+返回概述 / 注册表列表行引用 / 配置 server 名任一即合规 +
  钉「不索输出原文/完整回显/行号」+ 钉「ls 磁盘与列表行两种出处形态任一即合规」
  （治聚类 3 的一半——vio1[3]「靠列表行在册就标已验证，未做注册表行证据核验」）。
- **方框二·无差别已验证**（vio2）：block 面=全绑定已验证 **且** 留痕同形泛化（组合
  条件，防「全已验证但各附命令」被误伤）；legal 面=绑定级差异化留痕 / 混合三态 /
  全已验证但各附出处即合规 + 钉「无证伪不须声明」+「三态按绑定标注即合规、不须逐
  类别拆标」（沿用 plan:2#3 v5 定稿词形）。
- **方框三·假设缺置信度或影响**（vio3，**双面源钉词形一钉双治**，㊺）：block 面=
  假设条目无置信度或无错误时影响 **任一**缺席即 block；legal 面=**定性等级（高/中/低）
  + 影响描述两要素在场即合规**，显式禁索数值化（0.9/百分比/概率区间）、禁索量化范围/
  回退命令/降级步骤/返工成本（治聚类 1）+ 钉「置信度+影响只对假设态要求，已验证/
  证伪态不须」（治聚类 2）。
- **方框四·漏绑定核验**（vio4）：block 面=S3 绑定集中某绑定无任何四类核验留痕、被
  「随 X 覆盖/同 X 已验证」代过；legal 面=每绑定独立核验段（不适用类附显式声明）即合规。

**形式要件行的操作化**（第二十六例 ③ 教训：form 行措辞本身是 clean 磁体）：
基线 form「每绑定四类核验留痕；三态逐绑定标注；出处/置信度+影响/理由齐备」有两处歧义
致 clean 误伤——①「四类核验留痕」未定义**不适用形态**（聚类 3）；②「出处/置信度+影响/
理由齐备」并列写法被读成**三者对每绑定都要**（聚类 2）。反转版 form 双侧钉死：
「某类对该绑定不适用时附显式『不适用』声明即算该类留痕」+「已验证态附出处，假设态附
置信度+影响，证伪态附理由（置信度+影响只对假设态要求，已验证态不须）」——**三态与
字段的对应关系写进 form 行**，不留给 judge 临场分配。

【判材边界】（治聚类 3/4）：真实环境真值（PATH/磁盘文件/MCP 连接/venv 依赖）不可见
->只判留痕在场与 trace 内自洽；不适用声明即合规（skill 类绑定无 CLI/MCP 依赖、CLI
类绑定无 skill 条目、零 skill 绑定四类多不适用）；④环境前提以命令+返回概述留痕即合规，
不复核充分性/覆盖面（禁索 frontmatter 依赖项/脚本可执行性/venv 路径/API key/编辑
工具依赖）；只标注不裁决=假设接受留子6，不得以「未裁决假设」block。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **同一形式契约在不同节点复现时，mech 复用优先于措辞迭代——「三态标注+假设附
   置信度×影响」是跨节点通用契约**（第二十四例① 的第二实证，成本侧新论据）：
   plan:2#3 为这条判据烧了 **v1-v5 五轮措辞**才认输下沉 mech；本节点在 **v1 一轮**
   即识别同款崩法并直接复用同一函数（零正则改动、零变体）。**识别信号=判据文本
   同构**（「三态标注：已验证/假设/证伪 + 假设附置信度×影响」在两个节点 purpose 里
   近逐字一致）——设计阶段扫一遍兄弟节点的 purpose，形式契约同构就先查 mech 注册表
   有没有现成的，别从基线措辞重新迭代。操作化进 #30 playbook ①（前置 pin 审计）：
   **加一步「查 mech 注册表有无同契约现成函数」**。
2. **双侧钉死自相绞杀是 mech 下沉的第三类信号**（⑤/㊳ 的合流，前两类=压跷跷板、
   负判定齐崩）：方框三要治「禁索数值化」（legal 面必须写「定性即合规」）又要拦
   「两要素双缺」（block 面须扫在场性）——**legal 面的宽度直接钝化 block 面的扫描
   动作**，措辞无解（写得越清楚 judge 越只读 legal 面就停）。判别锚=写方框时发现
   「block 面和 legal 面在描述同一个字段的有/无」，且 legal 面必须放宽（因为基线
   误伤源正是该字段的过度索取）→ 直接下沉，别试措辞。与第二十六例② 的差集型跷跷板
   并列为「结构性无解」的两个形态。
3. **form 要件行的三态×字段对应关系必须写全，并列式「出处/置信度+影响/理由齐备」
   是 clean 磁体**（第二十六例③ 的第二实证，本例最便宜的一处修正）：基线 form 用
   斜杠并列写三态各自的字段要求，judge 读成「三者对每绑定都要」→ 误判「B1/B2/B4/B5
   已验证项未附置信度/影响」（聚类 2）。反转版把对应关系逐态写明：「已验证态附出处，
   假设态附置信度+影响，证伪态附理由（置信度+影响只对假设态要求，已验证态不须）」。
   操作化：**form 行凡出现「A/B/C 齐备」式并列，必须显式绑定每项的适用条件**——
   斜杠并列在弱 judge 眼里是合取不是分派。
4. **「不适用」是四类核验型判据的法定第五态，form 与判材边界须双侧钉死**（本节点
   特有的枚举完备性问题）：四类核验（skill/CLI/MCP/环境前提）对任一绑定天然有不适用
   项（skill 类绑定无 CLI 依赖、CLI 类绑定无 skill 条目、零 skill 绑定四类多不适用），
   基线 form 只写「每绑定四类核验留痕」→ judge 把「②CLI 不适用--显式声明」判成
   「无留痕」（聚类 3，且顺带把 vio1 的牙污染成错理由牙）。钉法=form 内联「某类对该
   绑定不适用时附显式『不适用』声明即算该类留痕」+ 判材边界枚举三种不适用场景 +
   合法正例给一条纯不适用行。**泛化**：凡「对每个 X 做 N 类核验」型 form，先问
   「N 类里有没有对某些 X 天然不适用的」——有则不适用形态必须进 form 行，否则
   judge 必把「不适用」读成「漏做」。
