### L5 条款设计（红队材料包钉死）

基线实证的三层浪费全在 agent 侧：①prompt 零材料（模型手写极简 prompt）→
agent 从零重勘；②agent 全工具 → grep/codegraph/python 重算全来一遍；
③三攻（候选4/提案/候选2）超出「攻击领先方案」语义。条款三钉（全部框架
通用措辞，零项目语义）：

1. **材料随迁进 prompt**（#14 的 agent 变体）：红队 prompt 必须逐字携带
   攻击对象材料包——候选描述+子3 五项核验结论+本步矩阵评分理由（主段
   上下文中全有，复制操作零新取证）；
2. **红队职责=基于材料的独立判断攻击**：攻击面=设计逻辑/一致性/遗漏风险，
   存在性/影响面/数据契约以子3 留痕为准不重验（引用子3 出处即合法）；
   禁重跑 codegraph/grep 全仓/重算数据文件——确需复核时 Read 单点文件
   定点核对（按条配额：每攻击点至多 1 次单点 Read）；
3. **攻击对象=领先方案一次**：触发条件（分差小或跨模块）满足时攻击排序
   第一候选；多攻须逐条附理由（为何领先方案攻击不足以覆盖）。

**gate 零变更三查**（#29 程序）：①mech 词表——pugh_* 两条扫描 trace 文本
词形，不受条款影响；②judge 方框——「在未触发前提下额外自愿对某候选跑
一次红队=加强不是留痕缺失」为既判合法形态，L5 限的是**触发后的攻击对象
选择**（领先方案），与 gate「多跑不判 block」方向相容（gate 是下限非上限，
条款约束行为面不动判据）；③复用引用/材料包引用形态不命中任何现存 block
条件（方框一要求理由含子3 具体核验值——L3/L5 同向）。
