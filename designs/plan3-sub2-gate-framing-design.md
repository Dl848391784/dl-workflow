## 2. 反转后的判据设计（默认-PASS framing）

结构：形式要件（保留 `_CTS_STEP2_FORM_REQUIREMENTS` f-string 单源）+ 默认 pass 声明 +
**四方框**（每条 block 面+legal 面近端双侧钉死，词形取 §1.1 误判判词逐字）+
【判材边界】段 + 【合法正例】段 + 条款引用要求。

- **方框一·幽灵能力**（vio1，跨参照㊻）：block 面=强制路由/绑定引用的能力名在 trace
  自述①清单或②出处中无对应条目判 block（逐字例：路由加载 `factor-pool-optimizer`
  但①②均无此名）；legal 面=每个能力名附注册表出处即合规 + **枚举可列主要条目+「等」**
  （治聚类 3）。判面=trace 内自洽，不核真实注册表。
- **方框二·强制路由漏核**（vio2，跨步一致性）：block 面=代码改动任务（改 .py）的路由
  未列 H15 codegraph 留痕或 superpowers 触发任一判 block，任务集取 S1 逐任务核对覆盖；
  legal 面=**同类型任务合并说明即合规**，不得要求逐任务四列表格/逐条展开/§2 触发词
  逐字原文（治聚类 1+2）。
- **方框三·凭记忆编造**（vio3，负判定→正判定改写）：block 面=能力功能描述在场却无
  SKILL.md/listing 出处引用判 block；**附显式检测步骤**（逐条检查①清单条目，凡含功能
  描述性短语则须附出处，描述在场而出处不在=block）——v1 缺检测步骤致 vio3 崩 2/6；
  legal 面=只列能力名+出处不写功能描述即合规 / 描述附出处即合规，不索取 SKILL.md 全文。
- **方框四·②无逐任务说明**（vio4，形式+一致性）：block 面=②声称「内置足够/零 skill」
  却无逐任务归属说明，或②结论与强制路由实际绑定矛盾判 block；legal 面=②归属说明在场
  且与路由一致即合规 + **条件触发不属常驻绑定**（治聚类 6，v1 clean 残余误伤）+
  「零 skill」是合法结论（双结论制不被反读成违规）。

【判材边界】（治聚类 2/3/4/5）：真实注册表（available-skills 列表/磁盘目录/MCP 配置/
CLAUDE.md §2 原文）结构性不可见->只判 trace 内留痕在场与内部自洽，不得以「无法核实该
能力真在注册表/该触发词真在 §2/available-skills 列表未逐字呈现」block；codegraph 留痕=
声明查询动作即合规，不索取具体命令形/原始输出回显；任务类型以 trace 自述为准，不得以
「测试执行实质涵盖写代码前 TDD 环节应命中 TDD 触发」block。

【合法正例】（各聚类合法形态落位）：同类型任务合并路由说明；能力名=列表行；「改 .py 前
codegraph impact 查询留痕」（声明动作即够）；②逐任务归属说明（绑定项+内置足够项）；
只列能力名+出处不写功能描述（不触发方框三）。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **负判定方框须给「扫描动作」不只给 block 面描述**（㊳ 操作化补充）：v1 方框三写
   「功能描述出现却无出处引用判 block」（block 面完整），vio3 仍崩 2/6；v2 加
   「检测：逐条检查①清单中每个能力条目，凡条目含功能描述性短语（…），该描述须…」
   即升 5/6。**区别**=前者是判定标准、后者是**遍历指令**——default-PASS 下 judge 不
   主动遍历，须显式命令它逐条扫。plan:2#2 的三 mech 走了下沉路线，本例证明**措辞层
   给遍历指令亦可救**（成本远低于 mech）。操作化：负判定方框（合法留痕缺席才违规）
   写完 block 面后必加一句「检测：逐条检查 X，凡 Y 则须 Z，Z 不在=block」。
2. **双结论制节点的「合法结论」须在方框内显式免责**（㊽ 变体）：本节点②「零 skill」
   是设计明写的合法结论，但方框四的 block 面「声称零 skill 却无逐任务说明」被弱
   judge 有反读成「声称零 skill 即可疑」的风险——v2 钉「『零 skill』是合法结论只要
   逐任务说明在场」显式共存（㉓ 双侧化在 block 条件内部）。凡 purpose 侧写了「X 是
   合法结论」的双结论制节点，gate 方框须同步免责，否则 framing 反转后 judge 仍拿它
   当违规信号。
3. **条件触发 vs 常驻绑定是能力配置类节点的通用歧义**（fixture+判据双侧）：clean 写
   「skill X 仅在条件 C 时触发」与②「零 skill 绑定」并存，弱 judge 读成矛盾。双侧
   处置=载荷侧不混写（清单归清单、绑定归绑定）+ 判据侧钉「条件触发不属常驻绑定，
   ②归属说明覆盖常驻绑定即可」。plan:3 子3/子5 同族（都涉绑定语义），泛化时可
   preemptive 套用（⑦ 从「翻车后归因」前移为「设计时预防」）。
4. **遍历指令过宽会反伤 clean——「标注 vs 描述」须在同方框内结构可区分**（⑬ 第四变体，
   本条与沉淀 1 是同一旋钮的两端）：方框三为救负判定加了「逐条检查①清单每个能力条目，
   凡含功能描述性短语则须附出处」遍历指令（沉淀 1），生产复跑暴露它把
   **纯出处标注**「`factor-development`（列表行）」也扫成「功能描述无出处」（clean 4/6）。
   修法不是撤遍历指令（撤则 vio3 回崩），而是**在方框内加关键区分**：
   「（列表行）/=available-skills 列表行『X』是纯出处标注不是功能描述，本方框只在
   出现『说该能力做什么』的描述句时适用」。**操作化**：加遍历指令后必须问「被遍历的
   字段里有没有形态相近但合法的东西」，有则同方框内钉死区分线——遍历指令与区分线是
   配套的，只加前者=把负判定崩牙换成 clean 误伤。
5. **㉘「落地后必须重跑」的第二实证（本例白捡一轮的反面：捡到了）**：v2 候选 clean 6/6
   即落地，落地后按 ㉘ 对生产 gate 复跑（gate==candidate 逐字断言已过，故排除文本
   差异）clean 掉 4/6——**同文本同 fixture 的轮间方差把残留误伤面暴露出来**。若信
   「候选达标即完工」不复跑，这两处残留（列表行/磁盘目录）就带进生产。㉘ 原文说的是
   「有 f-string 插值时候选≠生产」，本例补充：**即使逐字一致也要复跑**——理由不同
   （不是文本差异而是方差采样），动作相同。
