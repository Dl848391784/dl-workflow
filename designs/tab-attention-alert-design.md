# 页签关注提醒设计（标题闪动 + favicon 红点）

> 日期：2026-09-02 · 状态：用户批准（「1和2就行了吧」——标题闪动+favicon，不做系统通知）
> 动机：工作流停在 NEED_USER/门栏没人发现（症状 AQ 族「工作流停了没人问」），
> 跑完也无感知——dashboard 页签需要被动提醒。

## 1. 触发源与事件

复用 SSE `/api/events` 的 workflows 全量推送（指纹比对前挂检测器），后端零改动：

| 事件 | 判据（scanner 已下发字段） | 图标 |
|---|---|---|
| 待确认 | `isWaiting(w)` = need_user ∥ gate_actionable，**跃迁**进入 | 🔔 |
| 跑完 | `w.gate === "done"`，**跃迁**进入 | ✅ |

只响应跃迁（上一轮无、本轮有），常驻状态不重复闪。首轮 SSE 静默播种
（否则打开页面时存量待办立即误闪）。

## 2. 两层提醒语义

- **标题闪动**：`document.hidden` 时才启动（人盯着页面时卡片就在眼前，
  闪动纯骚扰）；1.2s 轮播 `🔔 <name> 待确认` ↔ 原标题，多项合并
  `🔔 N 项待处理`；`visibilitychange` 回可见即停并恢复原标题。
- **favicon 红点计数**：canvas 动态绘制（无静态 favicon 资源，直接画圆+数字），
  计数 = 当前 waiting 数 + 完结未读数；常驻渲染（闪动停后的视觉残留标记）。
  完结未读集在页签重获焦点时清空（=已读）；waiting 数随状态实况消长
  （用户答完题自然清零）。恢复默认 = 移除动态 link 元素回退 /favicon.ico。

## 3. 实现

纯前端单文件（dl_dashboard/static/app.js 末尾加 TabAlert 模块 + es.onmessage
挂一行调用，~90 行）。实例删除时清理其完结未读条目。error 实例不参与提醒
（状态不可读，侧栏已有 err 红点）。

## 4. 验证

- node --check 语法 + DOM stub 驱动跃迁用例（首轮静默/wait 跃迁闪动/
  done 跃迁入未读/答题后清零/焦点清空未读/多项合并文案）。
- 真实实例 E2E：重启 server 确认新 JS 下发（mtime 版本戳），
  用户浏览器实际过一遍待答/完结场景。
