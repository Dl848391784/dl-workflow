## 2. 杠杆 1：u:1#4 双向取证加「模式枚举二态」

**判据**（③内部仓库层新增形式要件，purpose/selfcheck 披露）：
根因/问题机制指向可文本检索的代码写法（表达式/调用/写法形态，如 `* 100`）时，
必跑全仓枚举，载荷载「模式枚举」q 项 = 命令原文 + 命中清单（文件:行号，全量不截断）
+ 范围声明（全仓或限定目录+理由）；机制为单点逻辑（不可文本枚举同族）时，
载「模式枚举：不适用——<一句理由>」。**二态必居其一，禁沉默。**

**分层**（§3.5 #1/#12）：
- 机械层（新 qa mech `pattern_enum_declared`）：模式枚举项存在性 + 形态
  （非「不适用」则清单须含 文件:行号 形态）——存在性/词形判据下沉，零 judge 方差。
  无条件触发（非代码问题写「不适用」一行即过，#7 低成本合法路径在场）。
- judge：不新增判面——真值（命令是否真跑/清单是否真实）judge 判不了；
  消费侧兜底 = plan:1#2 用户拍板时看到全量清单（真值归用户）。
  gate 顶部 mech_scope 括号补一句（模式枚举存在性已机械校验，勿重复判/
  不得发明枚举质量要件）。

**价值**：plan:1#2 范围抉择基于 9/9 全量病灶清单出题，而非被预过滤的 6/9。

## 3. 杠杆 2：plan:2#4 归一化步骤加「回归防护显式抉择」

**判据**（purpose/selfcheck 披露）：change_point 含源码（非 test 文件）（改|删|增）
条目的批次，二态必居其一：①带测试条目项（change_point 含 test 文件 （增|改） 条目）；
②在任一项 boundary 载「回归防护：无测试——<理由>」。**禁沉默。**

**分层**：
- 机械层（新 statements mech `regression_guard_declared`）：源码改动在场 ∧
  无 test 文件条目 ∧ 全载荷无「回归防护」标记 → 当场拒，报错文案指明二态写法
  （#5 判词要指路）。触发条件 = 文件路径集合运算（test 词形：test_*.py /
  *_test.py / test_cases/ / tests/），机械可判零裁量。纯测试/纯文档改动不触发
  （宁纵勿枉）。
- judge：不新增判面；gate【判材边界】补 mech 钉句（二态存在性已机械校验，
  勿重复判；理由充分性不判——归用户 plan 门栏审）。

**价值**：「要不要测试」从模型自由裁量变成显式留痕裁决点，用户在 plan 门栏可否决。
