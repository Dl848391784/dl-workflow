## 0. 本节点与前例的结构差异（决定判面怎么切）

| 维度 | u:2#1（最近邻，子1 同族） | **u:3#1** |
|---|---|---|
| record_format | qa | **qa**（mech 下沉可行，#30 ⑰） |
| mech_checks | 三项（value_no_unsourced_inference / answer_source_marker / goal_candidate_traceability_alignment） | **无**（基线先判 judge 侧能否稳） |
| artifact 组成 | 单条（子1 是首步） | **单条**（子1 是本节点首步；跨节点 minor_stage 过滤后无前序拼合） |
| 输入锚 | ProblemContext 存活问题 | **GoalsAndValue.step4.statements**（跨节点吃 must 目标集——但不在 artifact 内，judge 看不到目标集原文） |
| 命题性质 | 目标引出（who/outcome/价值 三类覆盖） | **障碍引出**（KAOS 否定提问 × 约束类型 ≥3 类 × 双结论制） |
| 形式要件常量 | `_G2_STEP1_FORM_REQUIREMENTS` | **`_S3_STEP1_FORM_REQUIREMENTS`**（purpose+gate 双引用，单源） |
| gate 长度 | 反转后 2000+ | **基线 ~330 字（含常量展开约 700）**——短 gate thrash 第七实证候选 |

由此而来的设计约束：

1. **judge 判材缺口（本节点独有）**：形式要件要求「对每个 must 目标做否定提问」，
   而 must 目标集在 `GoalsAndValue.step4.statements`——**跨节点，不在 artifact 内**
   （`read_evidence_for_step` 按 minor_stage=ScopeAndConstraints 过滤）。judge 无法核验
   「是否覆盖了全部 must 目标」，只能判 trace 内自述的目标数与否定提问数是否自洽。
   这是 #7「判据要求的佐证必须有低成本合法获取路径」的 judge 侧变体：**判不了的不判**，
   须显式钉死「不得以『无法确认 must 目标集完整』为由 block」。
2. **三条质量判据分类（#30 ⑫）**：
   - C1 空泛复述（「数据可能不准」无具体对象）= 语义主导，但「有无具体对象」有词形面。
   - C2 否定提问形式主义（每目标同一句套话）= 语义（套话 vs 具体化）。
   - C3 ②偷懒（缺任一 must 目标的否定提问留痕）= 形式，但判材缺口见 1（判不了完整性，
     只能判「有没有否定提问留痕」这一存在性）。
3. **约束类型 ≥3 类的判定面**：形式要件枚举 6 类（代码库结构/项目硬规则/数据契约/
   环境工具链/外部依赖/时间资源）。弱 judge 可能发明「必须逐类命名分类标签」要件——
   须钉「按内容归类可判即合规，不要求逐条打标签」。

### 1.1 误伤模式聚类（clean 6 轮判词逐字）

| # | 模式 | 判词摘录（逐字） | 性质 |
|---|---|---|---|
| 1 | **q/a「按序对齐」被读成「一问一类映射」** | 「q/a『按序对齐』要求每条 q 对应一条 a 顺序一一映射，q2/q3/q4 分别只覆盖 G1 的三类」 | judge 发明要件（q/a 实际 7/7 等长按序） |
| 2 | **用户侧三项被读成逐项必答** | 「缺少对用户侧'人力'约束缺口的补问或已有原话依据；仅询问并回答了时间与权限，未覆盖人力」 | 判据自身措辞歧义（同 u:2#3 聚类 1「逐项齐全」型，#23 修文本不站队） |
| 3 | **≥3 类被读成六类全覆盖** | 「缺类型覆盖中「外部依赖」类；判据要求类型覆盖≥3类，实际覆盖 4 类，但外部依赖类完全缺失（属≥3类基线外的盲点，**严从裁量**）」 | judge 发明要件（判词自承从严 framing 致病） |
| 4 | **约束候选的反事实假想被当「无出处推断」** | 「C2.2 freshness 仅写『若 data_date 早于2026-07-24则不存在』是推断式陈述…按判据『无出处的推断禁止写进结论』」 | 判据适用面错位（**本步命题性质=KAOS 反事实假想**，真伪验证在子2；「无出处推断」只约束结论句） |
| 5 | **分类归属正确性之争** | 「C1.1 是 H 规则应归项目硬规则类，C1.2『web_ui 只读不改后端』也是 H 规则同应归项目硬规则，被错归代码库结构」 | judge 发明要件（形式要件只要求覆盖 ≥3 类，未要求归类归属正确） |
| 6 | **出处须「可核验」** | 「C2.1 声称报告字段名来自用户原话但未给出可核验出处」 | judge 发明要件（同 u:2#1 聚类 2「可核验性」族） |
| 7 | **must 目标集完整性无前序对照** | 「前提『GoalsAndValue 子4 归一化』未提供 must 集合证据，模型自行界定为 1 个 must 目标无前序对照」 | **判材缺口**（§0 约束 1 预判命中：must 集跨节点不在 artifact 内，judge 判不了） |

7 类中 5 类是 judge 发明要件（1/3/5/6/7）、1 类判据措辞歧义（2）、1 类判据适用面错位（4）。
非纯词形可改根除（非 ⑱ 一轮达标条件），但聚类 4/7 是**本节点独有的结构性钉死位**：
候选=反事实假想、must 集跨节点不可见。

## 2. 设计决策

1. **framing 反转**：默认 pass + 明列 block 条件（「默认 pass」字面=run_judge 双态同向单源，v2.76）。
2. **判据文本歧义修复**（聚类 2，#23 修文本不站队）：`_S3_STEP1_FORM_REQUIREMENTS`
   「用户侧约束（deadline/人力/权限）缺口用 AskUserQuestion 补问」→ 补「三项是缺口检查清单
   非逐项必答：上下文已有原话或补问已覆盖的项即达标，本任务不涉及的项无需强凑」。
   常量单源=purpose 模型侧与 gate judge 侧同向（#29），无独立字面需手工同步（selfcheck
   未含该措辞）。
3. **【本步命题性质】段（聚类 4 钉死，本节点独有）**：约束候选是「若 X 则目标失败」式
   反事实假想，真伪验证在子2 三态定真伪——候选带具体对象即合规，不得以「候选是推断/
   未经验证/无事实出处」block；「无出处推断」只约束结论句。
4. **【判材边界】段（聚类 7+6 钉死）**：must 目标集跨节点不在载荷内，不得以「无法确认
   must 集完整/未与前序对照/自行界定目标数」block；「Read CLAUDE.md 原文…」「用户原话/
   AskUserQuestion 选中：'…'」即合法出处形态，不得要求可核验/更完整引用/贴行号。
5. **方框判据（形式类+语义类穷举，#30 ⑫）**：无 mech 下沉时形式要件违规必须明列为 block
   条件，否则「方框以外一律不判」会让 judge 停止执行形式要件（u:2#2 v2 教训）——
   一、类型覆盖 <3 类；二、候选空泛（不绑定任何具体对象）；三、否定提问形式主义
   （多目标共用同一句套话）；四、②偷懒（②申报且缺任一 must 目标否定提问留痕）；
   五、结论无出处推断未标「推测」。
6. **①②互不适用 + ②豁免类型覆盖**（双结论制守卫，#3）：不得以「缺②佐证」block ①、
   以「缺候选」block ②；结论②申报时第一条（类型覆盖 ≥3）不适用（②本就无候选，
   否则合法②载荷必被一条误伤）。
7. **合法形态四条**（聚类 1/2/3/5 逐条对应）：q/a 等长按序即达标（不要求一问一类）；
   用户侧三项非逐项必答；≥3 类达标不得因缺其余类 block；分类按内容可归即合规、
   归属之争不作 block 依据；单 must 目标一句否定提问=合规。

### 关键现象与教训

1. **一轮达标**（u:1#5 / u:2#4 后第三例）：7 类误伤中 5 类是 judge 发明要件，但全部被
   「合法形态近端钉死 + 方框以外一律不判」一次覆盖——framing 反转本身即治 clean
   （0/6→6/6），无压跷跷板，**无 mech 下沉**（vio 侧基线即全 6/6，judge 判得动）。
2. **候选文件 ≠ 落地版：形式要件必须回引常量全文，不能用压缩转述**（#30 ⑮/㉕ 的第三变体）。
   候选文件我把 `_S3_STEP1_FORM_REQUIREMENTS` 压成「约束类型覆盖 ≥3 类（编程域可选类：…）」
   一行，落地版按 #29 单源原则写 `f"形式要件：{_S3_STEP1_FORM_REQUIREMENTS}。"`——两者
   相差 189 字符，**重放验的是候选文本、生产跑的是落地文本**。一致性断言
   （`gate.replace("\n","") == candidate.replace("\n","")`）当场逮住。处置=按落地版重跑
   n=6（vio2 5/6→6/6，落地版反而更好：常量全文的六类枚举给了 judge 更强的具体化锚）。
   **纪律**：gate 内含 f-string 常量插值时，候选文件必须逐字包含常量展开后的全文，
   或落地后必须重跑一遍；「候选达标即落地」在有插值的 gate 上不成立。
3. **判据措辞歧义修复被证伪为不必要**（原设计决策 2）：聚类 2「用户侧三项被读成逐项必答」
   原计划改 `_S3_STEP1_FORM_REQUIREMENTS` 常量正文（#23 修文本不站队），实测 gate 侧
   【关键】段的双侧钉死（「三项是缺口检查清单非逐项必答…不得以『未覆盖人力』式单项缺失
   block」）已使 clean 6/6——**常量正文未动**。收益：少动一处 purpose 侧可见面（常量同时
   喂模型侧，改它会连带改模型行为），且并发期少碰一处共享文本。**判据歧义有两个修复位
   （常量正文 vs gate 方框），能在 gate 侧双侧钉死的优先钉 gate**——常量是模型侧+judge 侧
   共用面，改动波及更广。
4. **本节点独有的两个结构性钉死位**（可复用到同族节点）：
   - **【本步命题性质】**：约束候选=KAOS 反事实假想，真伪归子2 三态——不钉则 judge 拿
     「无出处推断」条款去判候选句（聚类 4）。**凡「本步产提案/假想、下一步定真伪」的节点
     （u:3#1 候选→子2 验证、u:3#3 范围提案→子5 拍板）都需要这一段**。
   - **【判材边界】**：must 目标集跨节点（`GoalsAndValue.step4`）不在 artifact 内，
     judge 判不了完整性（聚类 7）。**凡 `input` 字段指向另一 minor_stage 的节点首步都需要
     这一段**——`read_evidence_for_step` 按 minor_stage 过滤，跨节点输入结构性不可见。
