## 0. 本节点与前四例的结构差异（决定判面怎么切）

| 维度 | u:1#1-#4 | **u:2#1** |
|---|---|---|
| record_format | qa（#1-#4）/ statements（#5） | **qa** |
| mech_checks | who_no_repo_fact 等 3 条（#1） | **value_no_unsourced_inference 1 条**（v2.48 已下沉：价值/结论项推断词形「隐含/意味着/可能」） |
| artifact 组成 | 当前步+前序各步拼合（#3/#4） | **单条 trace**——子1 是本节点首步，`read_evidence_for_step(1,"GoalsAndValue")` 只回本步；ProblemContext 存活问题以 payload 内引述呈现（生产同形，#30 ⑨ 无拼合适配） |
| 命题性质 | 事实性命题 | **规范性命题**（外部证据无权证伪「我想要什么」，真值源只有用户）——故本节点无取证/裁决步，判据全围绕「用户原话出处」 |

| gate 长度 | 490–2397 字（从严版均 thrash） | **~370 字**（最短档；#30「短 gate 也 thrash」第三实证候选） |

由此而来的设计约束：

1. **vio 类型判定（#30 ⑫）**：三条质量判据里「空泛复述」「脑补目标候选」是**语义类**
   （须穷举违规形态为独立 block 条件），「②无佐证」是**形式类**（原话存在性，
   正面退路足够）。混合节点，钉死位按类分治。
2. **mech 已覆盖面可声明**：价值/结论推断词形是**无条件**词形扫描（无降级分支），
   可安全按 v2.34 范式声明「已机械校验、不得以此 block」。
3. **追溯判据的判材在 payload 内**：judge 看不到 ProblemContext trace（裁剪只取
   本节点），「候选对应不上存活问题」的判定只能依据 payload 内引述——钉死措辞
   须写明「以 payload 内引述的存活问题为对照基准」，防 judge 发明「须附
   ProblemContext trace 原文」要件。

## 2. 设计决策

1. **framing 反转**：默认 pass + 明列 block 条件（「默认 pass」字面触发
   run_judge 双态同向指令行，v2.76 单源）。
2. **判据文本歧义修复**（聚类 1，#23 修文本不站队）：常量
   `_G2_STEP1_FORM_REQUIREMENTS`「覆盖 who（受益者）/outcome（达成什么状态）/
   初步价值 ≥3 类」→「who（受益者）/outcome（达成什么状态）/初步价值三类
   均覆盖（每类 ≥1 条即达标，不要求单类多条）」；selfcheck 手写同词形
   同步改（#29：purpose 引用常量自动同向，selfcheck 是独立字面须手工）。
3. **机械校验声明**（v2.34 范式，聚类 3 + mech 已有面）：q/a 配对对齐与各
   答案非空（qa 配对写侧 v2.24 起无条件结构保证）+ 价值/结论推断词形
   【隐含/意味着/可能】（value_no_unsourced_inference，v2.48）——
   「已机械校验、不得以此 block、只判两件事真实性」。
4. **block 条件枚举**（#30 ⑫ 语义类穷举形态 + 形式类给正面退路）：
   - 一、结论①申报：(a) 脑补目标候选——与 payload 内引述的存活问题**零对应**
     （既非存活问题本身、也非其答案的用途延伸）才判；动作层承接即合规，
     不要求字面复述（聚类 5 钉死）。(b) 空泛复述——仅复述提问本身、无原话
     无事实才判；短答案+原话引用=合规（聚类 4 钉死）。
   - 二、结论②申报：无原话佐证判 block；合法佐证=本步补问回答原话；
     「未提及」未经补问不算（原判据语义保留）。
5. **【关键】交叉适用 + 原话形态钉死**（聚类 2/6）：①不适用②反之亦然；
   「用户原话：'…'」「原始请求：'…'」声明即合法出处形态——judge 看不到
   会话原文，禁要求可核验性/印证/更完整引用；补问原话写进答案即执行留痕，
   禁要求 evidence 体现 AskUserQuestion 调用轨迹（vio3[3][6] 发明要件）；
   结论末尾自检总括=合法元声明。
6. **【合法正例】**：demo clean 形态逐条对应误判类（三字 who 答案合规/
   初步价值 1 条合规/动作层承接合规），方框以外一律不判。

### 3.1 v1 候选（初版反转 gate，1408 字）→ 压跷跷板

|---|---|---|

clean 侧全好但 vio1/3/4 牙齿崩——pass 轮全部空判词（默认放行下直接没查），
逐 block 轮判词反推放过根因：

1. **vio1**：判据一（a)「目标候选…零对应」未要求**逐候选核对**——vio1 结论句
   只声明 G1 有出处，judge 按结论句判、不查插入的孤儿 G2（v2.81 #30 ⑫ 同型：
   笼统条件覆盖不了，违规形态须明列）。
2. **vio3/vio4**：条款二「无用户原话佐证判 block」需 judge 主动判定「这句声明
   算不算原话」——弱 judge 宽读：a5「用户字面请求即全部」被当作用户声明即
   佐证在场；who/outcome 项的原话被宽读为②佐证。block 轮判词（vio3[5]
   「这些均属会话原文佐证而非本步补问的回答原话」）正是缺失的钉死位。

### 3.2 v2 候选（单变量：只改 gate 文本，#30 ⑪）

- 一（a) 加**逐候选核对义务**：「逐个候选核对——任一候选零对应即判 block，
  不论结论句是否总括声明「全部有出处/全部承接」（总括声明不替代逐候选对应）」。
- 条款二穷举三种违规形态（#30 ⑫）：(a) 无引述裸声明（只写「字面请求即全部」
  无「用户原话：'…'」引述）/(b) 未问先引（「未提及」代替补问原话）/
  (c) 佐证不对口（who/outcome/价值项原话不支撑「无进一步诉求」声明本身，
  只有直接回答「是否还有进一步目标」的补问原话算）。
- clean 侧保护条款一字未动。

**v2 结果（1577 字）**：clean 6/6、clean2 6/6、vio3 6/6、vio4 5/6（②族全达标）；
**vio1 4/6、vio2 4/6 仍回炉线以下**。block 轮判词全部精准引用条款（一（a)/
一（b) 判对），pass 轮空判词=弱 judge 注意力方差——同文本两轮间 vio2
5/6→4/6 纯抖动，语义判据在弱 judge 能力边缘。**#30 ⑤ 压跷跷板信号确认**，
触发 ⑭：词形可判子项切出下沉 mech。

### 3.3 v3（mech 下沉 + gate 重划界，生产墙范式）

两个词形可判子项切出（零方差，append-trace 当场拒+指路）：

1. **`goal_candidate_traceability_alignment`**（治 vio1）：候选标签（Gx）集合
   ↔追溯项答案对齐扫描——孤儿候选（G2 只在候选项出现、追溯项不提）当场拒；
   宁纵勿枉：无 G 标签（②无候选）/无追溯项（q 无「追溯」）跳过交 judge。

   真实性」（硬连：追溯项提了 G2 但承接明显不成立——新载荷 vio5）。

## 4. 结论与遗留

1. u:2#1 完成 framing 反转：默认-PASS + 双方框（①张冠李戴单条/②佐证缺失族
   三条）+ mech 双下沉（候选标签↔追溯对齐、出处标注+who×原始请求）。
2. **本例对 playbook 的新增证据**：⑭的边界情形——词形子项切完后 judge 侧
   残留语义（承接真实性）仍在弱 judge 能力边缘时，下一步不是继续钉措辞，
   而是**问该判据是否摆错了节点**（子2 判材更优且本就覆盖）——判据归位
   优先于判据钉死。
3. **遗留（移交 u:2#2，并行会话）**：硬连载荷须进 u:2#2 replay 集；子2 gate
   的「矩阵放水/脑补挂接」条款是承接真实性的唯一判点，其反转若弱化该条款
   =覆盖链断。
4. **遗留（本节点自述）**：②申报时 outcome/价值项引述对口性只有 judge 单条
   薄条款+子5 用户读回兜底，无专门载荷——低风险（读回步用户亲见），
   如出现生产误判再补载荷。
