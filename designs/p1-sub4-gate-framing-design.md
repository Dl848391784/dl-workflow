## 2. 设计决策

1. **framing 反转**：默认 pass + 明列 block 条件（「默认 pass」字面=run_judge 双态
   单源，v2.76）。
2. **方框一·评分理由空泛不引事实**（聚类 1/2）：block 面=逐格理由只有形容词式断言
   （逐字取 vio1 词形「差不多/复杂一些/没什么区别/风险高/不太好测/规矩上麻烦点」）
   且不含任何子3 具体核验值。合法面四钉：①引用形式不挑（转写引用即合规，不得要求
   引原文/贴 file:line/标出处位置/要求该维度在子3 有同名核验条目）；②datum 写
   「=datum 全 S」即合规（聚类 1 直接反锚）；③S 格理由可以是「子3 未见该维度差异」
   （聚类 2 反锚）；④追溯段与红队段不是评分格，不得以「追溯段未逐项引事实」判本条。
   操作化：「判本条须逐格核对理由内有无子3 具体核验值（文件数与行数/impact 或
   callers 符号数/函数名或 file:line/H 编号/测试接缝事实，任一在场即合规）」
   ——㊺ 词形可判级切分线。
3. **方框二·替用户拍板**（聚类 6）：block 面=定案口吻（「最终选定/就这么执行/
   已确定/无需再问用户/直接剔除」）。合法面双钉：①「推荐提案＋待子6 用户裁决」
   在场即合规；②**权重陈述是权重提案不是替用户行使裁量**（不得以「预设权重/权重
   未经用户认可/未给权重映射表」block）；③**给出排序与推荐本身是本步产物**
   （「只提案不拍板 ≠ 不许推荐」——聚类 6 的一般化，防 judge 把本步产物当越界）。
4. **方框三·矩阵结论与评分矛盾（凑结论）**（聚类 4）：block 面双列=①净分数值与
   排序/推荐对应自相矛盾（净分高于 datum 却排后或不被推荐且无理由）；②净分数值
   与逐格 +/− 计数明显不符（1+ 3− 却记 +3）。合法面钉 Pugh 常规：「逐格 +/S/−
   本身的权衡判断不是矛盾（同一候选既有 + 又有 −、S 格计 0 不进净分、datum 由
   改动面选出而其余维度全 S 均是 Pugh 常规）」，不得以「S 项未计入净分/扣分维度
   取舍不自洽/datum 起点与某维度评分矛盾/该候选某维度也是 S 却总分为负」判凑结论
   （聚类 4 逐字反锚）。**操作化**：「判本条只核『逐格计数 ↔ 净分数值 ↔ 排序 ↔
   推荐』四者对应是否自洽」——把判面收窄到可机械对照的四元组。
5. **方框四·双向追溯漏项**：block 面=自述 must 集有目标在 forward 段无任何要素
   承接；或有要素在 backward 段回溯不到目标且未标注。合法面=**两向散文逐项即合规**
   （「『双向追溯矩阵』指两向对应关系逐项齐备，不指版式」——聚类 3 反锚）+ 多要素
   回溯同一目标合规（不要求一一对应/目标数=要素数）。
6. **【关键】段**（聚类 3/5 + 跨聚类兜底）：不得以「未呈现表格形式/datum 行缺失/
   理由未引原文或出处位置/未给权重映射表/红队既称未触发又跑了一次=留痕不完整」
   block 已附四要件的 trace；条件红队留痕=写出触发条件与本轮实际取值即合规，
   **未触发前提下额外自愿加跑一次并原文收录是加强不是缺失**（聚类 5 逐字反锚）。
7. **【判材边界】段**（㉚② 第三实例）：must 目标集与验收包属 GoalsAndValue/
   SuccessCriteria 节点，evidence 只含 DesignSolution 段=结构性读不到，不得以
   「无法核实 must 集完整/未与验收包对照/未附出处」block；双向追溯只判 trace 内
   自洽。**㉚① 本步命题性质**：本步只提案，选型/权重/假设的真伪与采纳归子6
   用户裁决，不得以「该推荐是否正确/该假设是否该接受/该权重是否合理」block。
8. **【合法正例】段**：六条逐字取自 clean 被误判的形态（转写引用/datum 全 S/
   S 格「未见差异」/红队未触发留痕/提案语义/forward 散文形式）。

### 3.2 v2/v3：两项跨项聚合判定下沉 mech（分治）

v2（2355 字）把「须动手数格」写进方框三 block 面 → **vio3 仍 1/6**（judge 读到
「须数格」也不数）；vio4 亦 1/6。两条同类：**跨项聚合（算术核对／集合差）默认-pass
下 judge 系统性不执行**，措辞两版无效 → 按 ⑤/⑭ 切 mech（能钉死先钉死已尽，压
跷跷板即切）。

- **forward 覆盖 → `pugh_traceability_forward_coverage`**（集合对齐第三例）：
  自述 must 集标签（`G\d+`）是否逐个带承接断言。㊴ 三点核对=**建变体不复用**
  `goal_candidate_traceability_alignment`：后者按「q 含追溯」取整条答案标签做集合
  差，本节点 must 集自述与承接声明同在一条答案内 → 自述侧标签自我满足、集合差
  恒空。**首版实现踩了同一坑的第二形态**：改按 `forward` 字样位置切分后半段取
  标签——实测生产形态里「自述 must 目标集={G1,G2}」常写在 forward 段**之后**
  （clean 与 vio4 载荷皆是），切分后自述集标签落进后半段，五载荷全 pass=mech 空转。
  定稿改**承接断言邻接判定**（标签后 24 字窗口内含 `←`/`<-`/`由`/`承接`），
  与段落顺序无关：backward 侧「要素→G1」与末尾自述集「={G1,G2}」均不含承接断言、
  不误计为覆盖。**教训**：集合对齐 mech 的「两侧」不能靠段落位置切，要靠**语义
  标记词形**——位置假设是载荷排版的函数，词形假设是判据的函数。
- **净分自洽 → `pugh_net_score_consistency`**（算术下沉首例）：候选段（`候选X：…净分 ±N`）
  内逐格 `+/−/S` 计数与自述净分数值比对（S 计 0，Pugh 标准算法无歧义）。宁纵勿枉：
  无候选段/无净分声明/解析不到格标注即跳过；datum（「=datum 全 S」无净分数值）
  天然跳过。
- gate 方框三/四改 ㉗ 范式声明「该项已由 append-trace 机械校验、不得以此 block」，
  judge 残留判面：方框三=「净分数值 ↔ 排序 ↔ 推荐」语义对应；方框四=backward
  镀金 + 承接声明真实性。
