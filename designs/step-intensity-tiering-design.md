# Step 强度三档设计（TACET / PIANO / FORTE）

> 状态：**待评审**（2026-08-21）。
> 提议：把 v2.40 取证深度三档（`designs/fetch-depth-tiering-design.md`）的「按问题性质分档执行」
> 思想推广到全工作流 44 个子步骤，粒度 = step（子步骤）。
> 命名采用音乐记谱法（用户 2026-08-21 选定）：TACET=本乐章该声部沉默 / PIANO=轻奏 / FORTE=强奏。

## 0. 与既有机制的三条边界（先划清，防概念混淆）

| 机制 | 与本设计的关系 |
|---|---|
| 取证三档（v2.40） | 本设计的**前身与组成部分**--u:1#4 的 per-atom tier 保留不动，step 级 intensity 是它的外层（#4 整步 TACET ⟺ 全原子 none，机械推导） |
| 成本优化系列（strip/pack/断链） | **正交**：那些是行为不变量优化（做的事一样，token 更少）；intensity 是**行为面变化**（做的事变少变轻，质量-成本显式交易） |
| 既有强度雏形（条件红队/双结论制/P3-1 读回确认级） | **被本设计收编**：条件红队=PIANO 的一个 profile 项；「零检查点合法」「零 skill 合法」「设计空间唯一合法」=TACET/PIANO 的合法出口，从「散落的目的文本」单源化为矩阵声明 |

命名碰撞处理：`Step.tier` 已被占用（decision/confirm 交互级，P3-1 读回降级），engine 另有
`handoff_tier`（交接包大小档）。新机制用 **`Step.intensity`**，值 `tacet|piano|forte`，
单源常量 `_INTENSITY_RULE`（对齐 `_FETCH_TIER_RULE` 先例）。

## 1. 三档语义（操作化定义）

| 档 | driver 行为 | gate 行为 | trace 落痕 |
|---|---|---|---|
| `tacet` | **不派段**（无模型会话、零 token） | 不跑 judge | engine 写 `tacet-record` 一行：触发依据指针（禁模型手写=禁自选 TACET） |
| `piano` | 照常派段，purpose 按 **PIANO profile** 渲染（降配任务面） | judge 判据按同 profile 取**子集**（与模型行为同源，防「模型做少了被全量判」=v2.49 自相矛盾同型） | 正常 trace + 定档记录 |
| `forte` | 现状（默认档） | 现状 | 现状 |

**默认档 = forte**（与取证档默认 light 的差异是刻意的）：取证 light 漏了有升档机制救回；
step 级 TACET **没有兜底**（质量损失不可见，成本损失可见）--漂向保守的方向选错时是成本问题
（易发现），漂向激进的方向选错时是质量问题（难发现）。**降档必须显式触发，永不默认**。

**升档**（对齐 v2.40）：PIANO 步内模型可提「建议升档 forte+理由」，gate 判；**禁降档**--
定档后执行面无裁量。**升档留痕**，建议未处理 = gate block。

## 2. 定档机制（谁/何时/怎么判）

### 2.1 三条原则（继承 v2.40）

1. **前置到便宜环节**：定档发生在「该步所需事实已齐的最便宜点」，执行面禁裁量。
2. **机械优先**（弱模型优先原则的直接应用）：能由 engine 从 state/trace 事实机械推导的
   档位**不交给模型判断**。模型/用户只出现在机械推导不可能的地方。
3. **防线删除类降档归用户**：降档本质是风险承担（规范性），凡触发条件含「删掉一道防线」
   （红队/多候选/检查点），须用户在 5 个 decision 步拍板；纯量减类（约束只验两类/指标封顶）
   机械触发自动生效，用户经 /dl status 可见、/dl 可改。

### 2.2 定档载体 = 任务画像事实（全部机械可查，零新增步）

不新增「画像步」--定档规则引用的输入全是既有 trace 事实：

| 事实 | 出处 |
|---|---|
| F1 外部知识依赖原子数 | u:1#2a `atomic_questions` 中 tier≠none 计数 |
| F2 MECE 原子数 | u:1#2a 原子清单长度 |
| F3 must 目标数 | u:2#3 分层提案 |
| F4 改动面文件数 | u:3#3 in 清单 |
| F5 不可逆操作数 | plan:4#1 五类清单 |
| F6 H9 单元数 / DAG 并行分支数 | plan:2#2 |
| F7 设计空间唯一论证在场 | plan:1#2 双结论 |
| F8 绑定能力数 | plan:3#3 |

### 2.3 定档时机 = 逐节点滚动（非一次性全局定档）

理由：u 阶段步的档位所需事实（F1-F4）在 understand 才产生；plan 阶段事实（F5-F8）在 plan
才产生。一次性全局定档要么太早（无据）要么逼模型预言。各节点定档点：

| 节点 | 定档点 | 机制 |
|---|---|---|
| u:1 | #2a（规划步，per-atom tier 同源） | 机械推导（F1/F2）+ gate 判 |
| u:2 / u:3 / u:4 | #1（=既有 5 个 decision 步之 3 个，NEXT_PREP 已并入） | 节点 intensity 草案并入该步 AskUserQuestion，**防线删除类用户拍板**，其余机械 |
| plan:1 | #2（decision 步第 4 个） | 同上（F4/F7 已在场） |
| plan:2 / plan:3 | #1 清点步末（本节点事实已齐） | **纯机械推导**（F6/F8），无 decision 步可用；deviation 只能升档 |
| plan:4 | #1 四源清点末 | 纯机械（F5/F6）+ 末步 /dl gate 展示全图回看（用户最终否决面） |

定档结果落 state（`node_intensity_map`），注入下一节点 purpose + /dl status + 交接包
（读回材料动态构建同 v2.41 SECTIONS_TEXT 范式）。

### 矩阵统计与读法

- **可 TACET 的只有 u:1#4 一步**（且纯机械触发）--这是诚实的结论：44 步里绝大多数是
  承重结构，「沉默」的合法面天然稀少。TACET 不是常规武器，是「全原子 none」时的机械事实。
- 可 PIANO 的 13 步全部落在**验证/质检/发散**三类辅助步；**引出/界定/归一化/拍板/基线清点
  恒 forte**（22 步）。防线删除类（红队 off/候选 2 个/检查点退化）3 处须用户拍板，其余 10
  步机械触发。

## 4. 执行面改动清单（评审通过后按 H8/H9 分批）

1. `dl_flow_nodes.py`：`_INTENSITY_MATRIX` 声明式单源（step → {legal, piano_profile,
   tacet_trigger, decider}），对齐 `ARTIFACT_SECTIONS` 先例；Step 运行时挂 `intensity`。
2. engine：节点入口 intensity 解析（读 state/trace 事实跑矩阵规则）→ state
   `node_intensity_map`；TACET=跳派段+写 `tacet-record`+judge 跳过；PIANO=purpose 渲染
   variant + gate rubric 子集（**同源取自矩阵，禁第二处手写判据**）。
3. 5 个 decision 步 purpose 补 intensity 提案项（AskUserQuestion 选项=矩阵合法档）；
   plan:2/3/4 #1 末机械定档落 trace。
4. driver：TACET 步进度区静音显示（statusline 「tacet」标记）；`/dl status` 展示全图。
5. 注入面：当前节点 intensity map 进 purpose（动态构建同 SECTIONS_TEXT）。
6. 测试：矩阵合法性（非法档组合不存在）/ TACET 跳段+落痕 / PIANO rubric 子集同源 /
   升档留痕 gate / replay 载荷入库（对齐 v2.36 起惯例：改判据必跑真实载荷重放）。

## 5. 防滥用与风险

- **TACET 滥用**（fetch 设计 §7 同风险面更大）：防线 = TACET 触发器**只存在于 engine 机械
  层**（模型无权选 tacet；trace 的 tacet-record 由 engine 写）；用户侧 /dl status 全图可见。
- **PIANO 判据双源漂移**：piano profile 的「模型做什么」与「judge 判什么」必须同一常量渲染
  （双侧单源，对齐 v2.24 双侧化先例）。
- **档位与成本优化叠加**：PIANO 步上的 strip/pack/断链照常生效，互不干扰（正交）。
- **在飞实例**：intensity map 对下一个 dl 实例生效（惯例，同 v2.38）。
- 升档救回弱于取证档：step 级 PIANO 漏掉的东西（如跳过的约束类）只在 review:0 显式暴露
  --接受残余风险，review 节「证据不足」项是最终兜底（同 fetch §7 逻辑）。
