## 0. 本节点结构（决定判面怎么切）

| 维度 | 值 |
|---|---|

| vio 类型 | vio1 要素无出处（编造）/ vio2 静默新增（二次创作）/ vio3 改写失真（语义偏移）/ vio4 原文未引用（判材边界） |
| gate 长度 | 基线 429 字——短 gate thrash 第十实证候选 |

由此而来的设计约束：

1. **「静默新增」真值结构性判不了，须重划为 trace 内自洽**（㉒ 判据归位 + ㉚②）：
   判据「静默新增设计包没有的要素=二次创作」的存在性真值=「E4 是否真在设计包里」，
   judge 无 design.md 文件可对照。判面重划为 **trace 内矛盾**：「新增候选：无」
   声明 vs 要素清单构成——清单含「新增/独立脚本/新建」措辞条目（如
   `scripts/category_summary.py` 新增独立脚本）却声明「新增候选：无」= 自相矛盾。
   「新增候选」区显式列出条目（含待子5 裁决语义）= 合法形态，不要求立即裁决。
2. **「无出处=编造」的出处语义与 plan:1#1 不同**：plan:1#1 出处=工具动词（codegraph/
   Read/Bash 等），本例出处=**design.md 行号 / evidence 指针**（文件引用非工具动作）。
   terrain_tool_trace 词表不适用——判面须重新定义出处合法形态。
3. **「原文引用」合法形态须钉死**（clean 误伤主源）：judge 把「要素原文引用进 trace
   正文」读成「须逐字整段嵌入单独字段/须贴行号对应段落/验收包假设也须逐条贴原文/
   须 evidence 文件名记录 ID」。合法形态=任一 q/a 答案中以『』/引号引用 design.md
   原文片段即合规，不要求整段/单独字段/验收包假设也贴原文。
4. **验收包/假设的出处要求收窄**（判面切分）：原文引用只针对①要素清单（保真基线
   核心——要素措辞是后续一致性判定的测量仪器）；②验收包（SC ID 自有结构）③假设
   （原样转录机制）只需出处行号即合规，不要求贴原文全文。
5. **改动类型「增」不是新增候选信号**：E3「paths.py 增加 CATEGORY_SUMMARY_RESULT
   路径常量（增）」中「增」=改/增/删三态之一，合法；「新增/新建/独立脚本」类措辞
   （新文件）才是二次创作信号。

## 2. 反转后的判据设计（默认-PASS framing）

结构：形式要件（保留三清单+出处+原文引用，但钉死合法形态）+ 默认 pass 声明 +
**四方框** + 【判材边界】段 + 【合法正例】段 + 条款引用要求。

- **方框一·要素来源自证不足（编造/静默新增）**：要素清单条目（file→function→
  改动类型形）声称提取自 design.md，却既无出处（design.md 行号 / evidence 指针 /
  原文『』引用）又未显式归入「新增候选」区 → block。两种违规形态穷举（⑫）：(a) 全
  清单裸=编造（「应该都在 design.md 里，按常规路径可查」类凭印象）；(b) 个别条目裸
  且未标新增候选=静默新增二次创作（「新增候选：无」声明下清单含「新增/新建/独立
  脚本」措辞条目）。合法形态=design.md 行号 / evidence 指针 / 『原文』引用 任一
  在场即合规；「新增候选」区显式列出条目（含待子5 裁决语义）即合规；改动类型「增」
  （新增路径常量/分组键）不是新增候选信号。
- **方框二·改写失真（语义偏移）**：要素自述措辞与 trace 内引用的 design.md 原文
  『…』明显语义冲突（原文「在既有聚合统计函数内增加分组键」vs 自述「重写为独立
  八维度聚合器」）→ block。判面=trace 内引文 vs 自述措辞自洽，不判与真实 design.md
  一致性（判材边界）。合法形态=措辞是对原文的忠实提取/适度压缩即合规，不要求逐字
  一致（「增加分组键」转述为「加维度分组」类语义等价转述合法）。
- **方框三·要素原文未引用**：①要素清单条目无任何 design.md 原文引用（『』/引号）
  → block（judge 无从核对保真度）。合法形态=任一 q/a 答案中以『』/引号引用原文
  片段即合规，不要求整段逐字/单独字段/行号对应段落复核。②验收包/假设只需出处行号
  （design.md:N）或「原样转录 design.md:N」标注即合规——**不得**要求验收包/假设
  也贴原文全文。
- **方框四·静默新增 trace 内矛盾**：见方框一 (b)（与方框一同判面双形态穷举，text
  不重复）。

【判材边界】（㉚② 跨阶段变体）：本步 input=designs/<主题>-design.md（主仓 .md
文件）+ DesignSolution 前步 trace——evidence 只含 TaskBreakdown 段，**两者 judge
结构性读不到**。不得以「未见 design.md 原文/无法核对出处行号真实性/无法确认某要素
是否真在设计包/无法核对验收包假设与 design.md 一致」为由 block；本步只判 trace 内
自洽 + 留痕形式。

【合法正例】「出处 design.md:12，原文『在既有聚合统计函数内增加 FACTOR_CATEGORIES
维度分组键，复用 factor_definitions.py 映射做 group key』」合规（原文片段引用即可，
不要求整段）；「SC1.1『报告展示八维度条数+占比可读出』（design.md:20）」合规（验收
包有行号+简短描述即满足，不要求贴 design.md 第20行全文）；「H1=…（置信度中×影响
中，原样转录 design.md:25）」合规（假设原样转录+行号标注即满足）；「新增候选：显式
『无』」+ 清单无新增措辞条目合规。方框以外一律不判。judge 判 block 须在 reason
引用判据条款并附 1 个正确改写范例（指模式不指实例位置）。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **「静默新增」存在性真值的三选**（㉒ 第二实例）：真值（E4 是否在设计包）结构性
   判不了时，判面重划为 **trace 内矛盾**（声明「新增候选：无」vs 清单含新增措辞
   条目）而非 mech 下沉（词形「新增脚本」与改动类型「增」语义区分脆弱）——先问
   「这个矛盾 trace 内可见吗」，比 p1-sub1 的「判据归位到子3」多一种解法。
2. **出处语义与判面绑定**：同一「无出处」判据，plan:1#1 出处=工具动词、plan:2#1
   出处=文件行号——mech 词表不可跨节点盲复用（terrain_tool_trace 词表不适用）。
   「出处」的定义（工具动作 vs 文件引用）先于判面设计。
3. **判面越界是发明要件的新来源**：judge 把「要素原文引用」判面越界到验收包/假设
   （要逐条贴原文）——判据未明说适用范围时 judge 取最宽。判据须显式声明「本判据
   只针对①要素清单，②③只需出处行号」。
4. **改动类型三态 vs 二次创作词形**：「增」态（新增路径常量）是设计包内合法改动，
   「新增/新建/独立脚本」（新文件）是设计包外二次创作信号——词形切分线=是否新文件
   形引用（.py 独立路径 vs 既有文件内改动点）。
