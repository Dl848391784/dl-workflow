## 1. 问题：子1 卡死在两个独立根因上

工作流 understand:1 子1（逼问问题定义）连续无法通过门控，且工具报错密集。
两层独立根因，须分别定性（block 三分类，rubric §3.6 #1）：

**根因 A（判据层）——judge 对「痛点可观察性」裁量漂移**：
- att1 block = 该抓（纯认知痛点「不合常理/不被采信」，无可观察后果）——健康返工，
  判词带范例逼出第二问，拿到真实可观察后果（「错误数字被用于选因子导致选错」）。
- att2 block = 判据缺陷：att2 已含用户确认的可观察后果（att1 判词范例逐字形态），
  judge 却发明「每条列举后果都须可观察」要件、按前轮判词描述判「未真正修复」。
  判据「痛点须可观察」从未定义**混合后果**（可观察+认知类同列）如何处理 → 裁量
  留白（§3.5 #4）；且用户自选答案即痛点事实，再 block 只剩「丢弃用户原话」/
  「第三轮重问」两条非法出路（§3.5 #7 佐证无合法获取路径）。

**根因 B（机制层）——手写载荷 → 解析拒 → 字节 hunt 死循环**：
- 模型绕过 `--scaffold` 直接 Write 载荷，标头粘内容同行（`【purpose】内容`，
  自然写法；scaffold 骨架是标头独占行）。解析器旧 regex `\s*$` 整行匹配把粘头
  行当「标头前多余内容」拒，报错「从【purpose】开始」——但文件确实以
  【purpose】开头，**报错指路与实况矛盾**。
- 模型据此怀疑隐藏字节，连环用 `head|xxd`/`od`/`python3 -c` 诊断：xxd/od 非
  白名单被 S15 围栏 deny、python3 能写被 deny，8 个工具报错零产出。
- 另有 block 返工文案「Edit 载荷」与 append-trace 落库即删载荷（防重复 append）
  矛盾，模型连环踩 file-not-exist / read-first。

## 2. 方案：三层系统杠杆（不换模型）

**v2.64 判据双侧钉死**（治根因 A）：新增单源常量 `_PAIN_OBSERVABILITY_RULE`，
purpose/selfcheck（模型侧）+ gate（judge 侧）三处引用——可观察后果作痛点本体
即满足；「要定位根因/修代码」=修复诉求不算；认知信任类（不合常理/不敢再用/
报告失信）自称「可观察痛点」也不算、同列=合法附带记录；仅纯认知痛点判 block；
模型侧退路=追问「这会改变什么动作/决策」或按②申报。
配套：block 返工文案对齐载荷生命周期（返工回路写进 block 文案/scaffold 成功
消息/落库成功消息三触点）。

**v2.65 解析器宽容 + 报错带 repr + S15 放行字节查看器**（治根因 B 的表征）：
- 标头 regex `^【([^】]+)】[ \t]*(.*)$` 放行粘头（group(2) 注入当前节首行）+
  剥文件头 BOM，模型自然写法直接通过（真实手写载荷四向验证：手写/BOM/干净骨架
  向后兼容/junk 报错）。
- 「标头前多余内容」报错附 `{val[:80]!r}`，BOM/散文一眼可见，免字节 hunt。
- `od`/`hexdump`/`xxd` 纯只读字节查看器进 S15 白名单（`>` 已一票否决挡写意图），
  python3 仍拒（能写，模型改用 cat/head/od）。

**v2.66 堵旁路正治**（治根因 B 的入口，用户质询「宽容是软解」后补）：
宽容化只是 defense-in-depth，模型手写粘头=手写格式=**四桶违规**（格式归脚本）。
正治不是接受它的格式，是让它写不了格式：
1. 主动指引（第一道）：注入 payload_format_hint 把 --scaffold 从「推荐」升必经
   路径 + 明示禁手写 Write（围栏 deny）。
2. 硬围栏（第二道）：fence S14 禁手写 Write `.trace-payload-*.md`，指回
   --scaffold（模型只 Edit 填「待填」）；S14 .jsonl deny 文案里「或手写 JSON」
   矛盾同步删。
3. 解析器宽容（第三道，v2.65）：只处理 scaffold 输出的边缘 glitch，不处理模型
   违规。

## 3. 验证

  （修对）/ 全认知+附带标注规避载荷 BLOCK（没开豁免口）。两轮逮住初版过松

- 解析器：4 向真实载荷验证（见上）+ pinning 测试。
- 围栏：Write .md deny+指路 scaffold / Edit 放行，pinning 测试。
