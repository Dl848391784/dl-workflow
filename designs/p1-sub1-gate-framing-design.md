## 0. 本节点结构（决定判面怎么切）

| 维度 | 值 |

| gate 长度 | 基线 448 字——短 gate thrash 实证候选（u:3#1 659 后一档） |

由此而来的设计约束：

1. **「引用不存在接口/模块判 block」是存在性真值判据，judge 结构性判不了**（§3 展开）：
   载荷内无 codegraph db，judge 无法对照真实符号表。基线 vio2 6/6 全部引「缺 codegraph
   原始输出/缺 file:line」（过判词形），**无一引「不存在接口」条款**=㉖ 预判的「设计内
   失牙」：clean 误伤修复（「原始输出」类词形合法化）的瞬间，这批牙同步掉。
2. **㉒ 判据归位优先于判据钉死**：存在性真值复核**已有更优判材位置=plan:1 子3**（其 purpose
   明列「①接口/模块存在性复核（候选引用的每个符号 file:line 核实）」）。子1 的位置 judge
   判存在性=用训练记忆比对训练记忆（凭空 API 的根源就是训练记忆不可靠）——矛盾操作。
   子1 判面收窄为 judge 能力边界内的三样：**留痕形式 / trace 内自洽 / 漫游**。
3. **判材边界钉死（㉚② 跨阶段变体）**：judge 以「未附 understand.md file:line/原文范围
   清单/无法核实范围对齐」为由 block=发明要件（输入跨阶段，结构性不可见）。「范围对齐」
   的判面=trace 内自述的勘察链路与 trace 内自述的问题陈述自洽（见方框三）。
4. **「codegraph 原始输出」歧义**（u:3#2 聚类 2 同族）：形式要件「每条事实附 codegraph
   原始输出或 file:line 出处」被弱 judge 读成「完整命令+完整返回+原文截取」——基线 6 轮
   clean 误伤 5 类是此族。须钉死合法形态：codegraph 输出简写引用（`codegraph callers X 输出
   N 个调用方` / `codegraph 输出 function X file.py:N`）/ `file:line` / Read 原文引用 /
   Bash 实测 `命令` 输出值，**任一在场即合规**；禁要求完整 stdout/命令原文/索引命令返回/
   Read 段落截取/understand.md 出处。
5. **数据契约类验证源**（u:2#3/u:2#1「可核验性」族）：④数据契约用 Bash 实测/Read 原文
   （paths.py 常量）即合规——形式要件是「codegraph 原始输出**或** file:line」的 or 关系，
   数据契约类验证源=Bash/Read（purpose 已披露），不要求 codegraph。
6. **新鲜度留痕**：声称「无需 sync」时附 Bash 实测时间戳+判定依据即合规（任一 q/a 内均可），
   禁要求单独留痕条目/命令原文/multiple 表核对。
7. **「ic_mean > 0」等口径断言**（clean 判词 [1] 误伤）：数据契约字段口径（`ic_mean`、
   阈值 `>0`）是已核实数据的合法断言，不构成训练记忆冒充——只要字段存在性附了出处
   （Bash 实测 schema names），口径判定就不必单独出处。

### 1.1 误伤模式聚类（clean 6 轮判词逐字）

| # | 模式 | 判词摘录（逐字） | 性质 |
|---|---|---|---|

| 2 | **Bash 实测跑了只写结论=不够** | [1]「字段口径 Bash 实测无实测原始输出、未列 parquet schema 字段清单（Bash 实际跑了但落库只写结论、未附原始 stdout）」 | judge 发明要件（要完整 stdout/字段清单） |

| 6 | **codegraph 输出简写引用不被认** | [6]「仅称『codegraph 输出在册』而无原始输出或 file:line」 | judge 发明要件（简写引用不算） |

6 类误伤全是**从严 framing 下 judge 发明「可核验的完整留痕」**（与 u:2#3「可核验性」族同
根因），加上判材边界（范围对齐要跨阶段文件出处）。误伤源=judge 发明要件为主，但合法留痕
形态词形明确（codegraph 简写引用/file:line/Read 原文/Bash 输出值），预期 framing 反转 +
合法形态钉死即治 clean（同 u:3#2 v1 一轮治 clean 的先例）。

### 1.2 载荷缺陷自审（#30 ⑦，先于 gate 迭代修）

- vio1（训练记忆）与 vio2（凭空 API）共享「无工具出处」判定面，但文本可区分：vio1=「一般/
  按惯例/通常」式常识断言（无具体符号），vio2=引用**具体符号**（`ic_stats.py:44` 等）却无
  出处。两者牙齿都靠方框一（现状事实无出处）接——但若方框一只写「无工具出处=编造」而不区分
  「训练记忆 vs 凭空 API」两个违规形态，judge 可能把二者读成同一判面。方框一须穷举两个违规
  形态为独立 block 条件（⑫ 语义判据穷举原则），并各自附合法正例。
- vio2 判词语义偏移（存在性→留痕）是**设计内**：凭空设计的符号本来就附不了出处——「引用
  具体符号却无任何工具出处」在子1 语境就是编造特征（真实现状必可附出处）。gate 须诚实声明
  判面边界：「本步判留痕，存在性真值归子3」。
- 基线 vio3 判词杂糅无关条款——方框三重划线后，VIO3 载荷期望判词真引「漫游/范围脱节」条款。

## 2. 反转后的判据设计（默认-PASS framing）

结构：形式要件（保留四要素+出处要求，但钉死合法形态）+ 默认 pass 声明 + **五方框** +
【判材边界】段 + 合法正例 + 条款引用要求。

- **方框一·现状事实无出处（编造）**：现状事实条目（①涉及模块/②可复用点/③调用方/④数据契约/
  新鲜度判定）声称已验证/已核实/已定位却无任何工具出处 → block。**已由 terrain_tool_trace
  mech 机械校验（零方差生产墙）**——引用了代码符号形（`.py`/`function X file.py:N`）却无任何
  工具动词的现状事实已被 append-trace 当场拒、不会到你这里。judge 侧不判「无工具出处/留痕不可
  核验/缺 file:line」——这些是机械已知事实。残留语义判面：（a）训练记忆冒充——「一般/通常/
  按惯例」式常识断言（即使未引用符号形）替代工具核实（「一般这类项目都有 utils.py」）；
  （b）引用具体符号的条目已机械校验，留痕在场但与声明来源明显矛盾（归方框二）。
- **方框二·内部矛盾**：trace 内声称的 codegraph 输出/Read 核实/Bash 实测结果与自述内容
  明显矛盾（如声称「callers 输出 0」却自述「影响 3 处」）→ block。judge 只判 trace 内自洽，
  不判与真实代码库的一致性（判材边界，见【判材边界】）。
- **方框三·漫游**：勘察链路与 trace 内自述的问题陈述/任务零相关（勘察了与「报告展示正 IC
  数量」零相关的日内择时/pipeline 内存治理）→ block。「范围对齐」判面=trace 内自述的勘察
  范围与自述的问题陈述自洽即合规，不要求 understand.md 出处（判材边界）。
- **方框四·新鲜度留痕缺失**：声称「无需 sync」却无任何新鲜度判定依据（Bash 实测时间戳/判定
  结论）→ block。附时间戳+判定即合规，不要求单独条目/命令原文/多表核对。
- **方框五·口径断言无出处**：数据契约字段/阈值断言（`ic_mean > 0`）声称已核实却无字段存在性
  出处（Bash 实测 schema names/Read paths.py 常量）→ block。字段存在性有出处后，口径/阈值
  判定本身不必单独出处。

【判材边界】（㉚② 跨阶段变体）：本步 input=understand.md 是主仓 .md 文件，evidence 只含
DesignSolution 段——judge 结构性读不到 understand.md。**不得以「未见 understand.md 原文/
未附 file:line/无法核实范围对齐/无法确认问题陈述完整」为由 block**；存在性真值复核归 plan:1
子3（可行性验证的接口/模块存在性核验），本步不判「引用符号是否真实存在于本仓」。

【合法正例】「codegraph callers _generate_ic_section 输出 1 个调用方」简写引用合规；
`summary/report/sections.py:32` file:line 定位合规；「Bash 实测 `sqlite3 …MAX(indexed_at)`
输出 2026-08-04 09:12 距今 <72h」合规（新鲜度判定不必单独条目）；「④字段口径 Bash 实测
schema names 含 ic_mean，正 IC 判定用 ic_mean > 0」合规（口径断言不必单独出处）；「勘察
范围与 understand.md 对齐：只勘察报告展示链路」自述声明合规（不要求附 understand.md 原文）。
方框以外一律不判。judge 判 block 须在 reason 引用判据条款并附 1 个正确改写范例。

## 3. 存在性真值 vs 留痕投影——mech 下沉决策（v1 重放后修订）

**初始评估**（v1 重放前）否决了 qa mech check 查 codegraph db 验证 trace 内符号存在性：

- **⑯ 可降级性红线**：`_implementation_nouns` 读 db 失败即静默跳过（「预检是增强层不是
  必需行为」）。若把存在性真值做成依赖 db 的 mech，db 缺失时机械层与 judge 层同时失守——
  judge 层又结构性判不了真值=该判据整体失效。要让 mech 成为「生产墙」须改 db 缺失行为为
  fail loud，属独立改动，超出本节点泛化范围。
- **㊻ create-vs-reference 脆弱性**：现状勘察的引用含「新增文件/新建脚本」类合法设计动作
  （候选方案会创建新文件），mech 须先解「引用已有符号 vs 声明创建新文件」的语义区分才能切。
- **㉒ 判据归位已消解该需求**：存在性真值在子3 有完整判面（子3 专门做逐符号 file:line 核实），
  子1 收窄为留痕+自洽+漫游后无真值判据残留。

**v1 重放实证**：纯 judge 侧方案（五方框，无 mech）clean 6/6 但 **vio2 2/6**——default-pass
framing 下 judge 看到 trace 整体出处齐备就不逐条审计，凭空 API 的裸符号引用（`ic_stats.py:44`
`count_positive_ic()` 无任何 codegraph/Read 动词）被 rubber-stamp 放过。这是 **judge 注意力
方差**（⑳/u:3#2 vio1 同型：编造类词形可判子项在宽松 framing 下 judge 不主动查）。

**修订决策**：区分两个可下沉子项——
1. **留痕投影（纯 token，⑯-safe）**：「该条回答引用了代码符号形（`.py`/`function X file.py:N`）
   却无任何工具动词」——词形可判，不读 db，不会降级。**下沉**新增 `terrain_tool_trace` mech
   （零方差生产墙）。这是 design §3 初始否决的 db 存在性 mech 的**非 db 变体**——⑯ 红线
   针对的是「db 缺失即跳过」的降级，纯文本扫描无降级面。
2. **存在性真值（db 依赖，⑯ 红线）**：符号是否真实存在于本仓——**仍归子3**（接口/模块
   file:line 复核），子1 不判。

mech 上线后 judge 侧 vio1/vio2 期望 BLOCK 但命中降为 0-5/6=**设计内委托**（生产墙先拒，
judge 只判留痕在场后的语义残项；u:3#2 同判读纪律，㉗）。replay docstring 与 §5 验证计划
按此更新。

## 3.5 mech 上线后的 judge 判面与读数口径

- **mech_checks=("terrain_tool_trace",)** 挂 plan:1 子1。
- judge 侧 vio1/vio2 期望 BLOCK 但命中降为 0-5/6 = **设计内委托**（生产墙先拒），
  replay docstring 写明「生产墙=mech 先拒，judge 侧读数=已知裁量面」。clean 仍 6/6
  （clean 全部符号引用都带工具动词/「未知」标注，mech 全放行）。
- vio3 漫游 / vio4 内部矛盾 是 judge 语义判面，必须 6/6。

## 4. 泛化沉淀候选（本节点新教训，先记不落 rubric）

1. **「存在性真值判据」结构性判不了时的三选**：判材归位（子3）/ 判面收窄（留痕自洽）/
   mech 下沉（被⑯红线+㊻脆弱性否决）——先问「这个真值有没有更优判材位置」，再问「judge
   载荷内可见什么」。子1 本例判面收窄+归位组合（㉒ 操作化第二实例）。
2. **牙齿保真度审计的判据归位判定**（㉖ 扩展）：vio 判词「命中但引错条款」不只在同判据内
   掉牙——当判词引的是**过判词形**（clean 误伤同源）时，修 clean 必连带掉牙；此时选择
   （a）该判据归位（真值挪走）、（b）该违规形态重划线（留痕语义）——本例选了 (b) 重划线
   为「引用具体符号无出处」（凭空 API 的留痕投影），保住牙齿且不牺牲判据意图。
3. **跨阶段输入的类型差异**（㉚② 扩展）：前 16 例的跨节点输入是另一 minor_stage 的
   statements（理论上读得到，只是过滤规则不喂）；本例输入是**主仓 .md 文件**（结构性永远
   读不到）。「范围对齐/与输入一致」类判据遇到文件型跨阶段输入时，不可见性是绝对的，判面
   必须下沉到 trace 内自洽。
