## 2. 设计决策

### 2.1 framing 反转（主杠杆）
「质量判据（从严裁量）」→「默认 pass--仅当以下成立才判 block」+ 方框化 5 条真值判据
（形式要件违规明列，#30 ⑫）：
1. 候选空泛复述（不绑定任何度量对象）
2. 追溯放水（零概念重叠硬挂 + 孤儿候选不处置）
3. ②偷懒（仅在申报②时适用）
4. solutioneering 残留（**重划线**：项目源码构件标识才违规）
5. 结论无出处推断（未标「推测」另列）

### 2.2 方框四重划分线（聚类 1/2/5 根治，本例核心）
`_SOLUTION_FREE_SUBJECT_RULE` 逐字规则列「字段名/管线名/组件名」为禁用，与本节点
clean 的合法形态**直接矛盾**（must 目标自带口径限定词必然入候选主语）——按 #23「判词与
规则文本矛盾时修文本不站队」，方框四改精化版：

- **违规侧**：项目源码构件标识——脚本文件名（`xxx.py`）/类名/方法名/函数名/模板文件名/
  CSS 类名/宏名/file:line（= vio4 的逐字判材）
- **合法侧**：用户已确认的数据口径限定词与交付载体——管线名/指标口径/数据日期/比较关系/
  报告/页面/字段值（= clean 的逐字被误伤词形）
- **判别线**：指向项目源码里的某个构件（改哪个文件/类/函数/模板）才违规，指向用户可见的
  数字与口径不违规

因此 `TestSolutionFreeRuleInGates._FIVE_STEPS` 的 `("understand",4,1)` 坐标须撤出逐字引用族
（u:2#4 v2.88 / u:3#4 v2.92 同范式第三次），改钉精化条款专用 pin（钉死意图不丢）。

### 2.3 两个可复用结构段（#30 ㉚，本节点均命中且更宽）
- **【本步命题性质】**：候选=提案，可检验化归子2/验收方式归子3/拍板归子5——**三个下游
  节点逐个点名**禁止代判（聚类 4）。u:3#1 只需点名子2，本例是该段的加宽实例。
- **【判材边界】**：**两个**跨 minor_stage 输入（must 目标集 + 范围约束）结构性不可见，
  且额外钉「补问选题不作 block 依据」（聚类 3）。

### 2.4 双结论守卫（#3）
①②互不适用：不得以「缺②定性理由」block ①；不得以「候选清单为空」block ②
（②本就无候选，方框一/二/四对②不适用——否则合法②载荷必被误伤）。

### 关键现象与教训

1. **两轮达标；v1→v2 的两处修复分属不同层，可独立归因（#30 ⑪ 单变量）**：clean 的
   1 例误伤在 **gate 层**（judge 发明「AskUserQuestion 补问需独立可核验出处」要件），vio1 的
   1 例漏网在 **fixture 层**（载荷含第二违规）——两者互不影响 clean/vio1 之外的读数，同轮
   同发不违反单变量原则（判据面与载荷面正交）。
2. **合法出处形态的钉死须覆盖「记录通道」不只「引用格式」（#7 交互通道接口审计的第三变体，
   v2.51 同族）**：方框五 v1 已钉「不得要求可核验性/贴行号/option ID」，judge 仍以
   「未提供该补问及回答出处」block——它绕开了「格式」面，从「**该记录是否存在合法通道**」
   面发明要件。修法=显式声明通道唯一性：「trace 内自述『经 AskUserQuestion 补问…用户原话
   （AskUserQuestion 选中）：…』即合法记录形态（本步无独立工具调用记录通道，自述即唯一
   记录形态）」。**凡判据要求「用户原话出处」的节点都要钉这一句**——否则 judge 会索取一个
   系统里不存在的通道（u:1#1 v2.51 的 `user_quote_channel` 是其 mech 侧对偶）。
3. **载荷保真度第五实例（#15/#30 ⑦）**：vio1 原设计只改 `a[1]/a[2]`（度量对象空泛）却顺带
   使 `a[4]` 追溯清单少列 SC3.1 = **孤儿候选未处置**，judge [6] 据方框二 block——命中方向对
   但引错条款，且导致另一轮 pass（judge 在两个违规间分散注意力）。修法=把 vio1 的追溯/孤儿
   处置补成完全合规，只在「度量对象」单点越界。**vio 载荷必须单点越界**：多点越界既污染
   条款归属抽读（㉖），又降低命中率。
4. **㉛ 三问预估被验证**：①方框一与方框四在「度量对象怎么写」上部分共享旋钮，但 vio4 的
   判材（源码构件标识）与 clean 的误伤词形（管线名/日期/口径名）可按「是否指向项目源码构件」
   **精确分线**，故未出现压跷跷板；②③如预判。实际两轮，与「低-中轮次」估计一致。
5. **牙齿保真度抽读结果（#30 ⑥/㉖）**：v2 五颗牙全部逐字引对目标条款（一/二/三/四/五 各自
   被点名），且**无一依赖已合法化的口径词形**——基线判词里 vio1/vio2/vio5 顺带引的
   「含『管线』=solutioneering」在 v2 判词中消失，牙齿改由各自方框独立支撑。方框四合法化
   未反伤任何一颗牙（§4 预判兑现）。

为何不可执行验证」= 真引；vio5 引「结论逐句须有出处」= 真引。**五颗牙全部真引目标条款**，
