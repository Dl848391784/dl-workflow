> 2026-08-04。§3.5 #28 泛化第五例、#30 playbook 第四例：把 u:1#1（v2.71）/#2（v2.72-75）/#3（v2.77-79）/#4（v2.80-84）验证过的「默认-PASS framing + 方框化真值判据 + 每条近端双侧钉死」应用到 understand:1#5。

## 0. 本节点与前四例的结构差异（决定判面怎么切）

| 维度 | 子1-子4 | **子5** |
|---|---|---|
| record_format | qa | **statements**（结构化载荷） |
| mech_checks | who_no_repo_fact / …/ redteam_three_piece | **空**——但 statements 分支有**内建**机械层 |
| 内建机械层 | — | 三字段非空 + `statement_fields=("confidence",)` 逐项非空 + 实现侧名词扫描（`_implementation_nouns`）+ 源步 ID 传导覆盖 |
| gate 长度 | 490–2397 字 | **326 字（全 workflow 最短）** |

两个由此而来的设计约束：

1. **`mech_checks` 在 statements 分支不执行**（engine `append_trace`：`_MECH_QA_CHECKS` 循环只在 qa 分支）。故本例若出现「压跷跷板」信号，**不能像 #2/#4 那样直接注册 mech_check**——须先补 statements 侧注册表，属独立项。本轮先只做 framing 反转，跷跷板出现则记为遗留。
2. **实现侧名词扫描是可降级预检**（codegraph db 缺失/git 失败则跳过该源，engine `_implementation_nouns` docstring 明示「judge 仍兜底语义」）。故该条**不能**像 #3 的「收录项数/骨架落盘」那样告知 judge「已机械校验、你不得判」——须保留为方框条款，只钉合法形态（boundary 字段含实现名词合法，只约束 text）。
   反之 `type_label`/`fields.confidence` 的**存在性与非空**是无条件 JSON 校验（不可降级），可安全声明「已机械校验、不得以此 block」。

## 2. 设计决策（草案，待基线误判判词逐字聚类后定钉死位）

### 2.1 framing 反转（主杠杆）
「质量判据（从严裁量）」→「默认 pass--仅当以下成立才判 block」+ 方框化 4 条真值判据：
1. 裁决不传导·证伪项混入（子4 判证伪的问题出现在陈述集）
2. 裁决不传导·边界超出（部分成立项陈述超出已证实边界）
3. 复合未拆（单句「和/以及/同时」连接多个独立痛点）
4. 实现侧名词未挪 boundary（text 含文件名/类名/file:line）

### 2.2 已机械校验项声明（不可降级项才声明）
`type_label`/`fields.confidence` 存在性与非空、statements 三字段非空 → 「已由 append-trace 机械校验通过，你不得以这些形式要件为由 block」。
**不声明**实现侧名词扫描（可降级预检，judge 是兜底层，见 §0.2）。

### 2.3 预期钉死位（基线判词到手后按聚类补）
按前四例经验预判并留位（**不预先钉死无实证的项**——#30 ③要求钉死位由误判判词逐字取）：
- 「证据不足」是合法 verdict（子4 四态之一），不得判「结论不确定=未定义完」
- 部分成立项**收窄**表述（「在 X 口径下」）是传导正确的合法形态，不得索取更强断言
- boundary 字段含 file:line/实现名词是**规定去处**，不得判「陈述含实现细节」
- 置信度/verdict 标签形式（type_label 取值域）已 mech，不判

### 2.4 实际钉死位（基线聚类 §1.1 逐条对位，全部有实证）
| 聚类 | 钉死位 | 层 |
|---|---|---|
| 1 语法主语 | 「中文省略主语合法」+【合法正例】「不得判缺主语/非陈述式/祈使短语」 | purpose+selfcheck+gate 三层（#29） |
| 2 定语当并列 | 条款三「修饰成分/约束枚举/定语不算并列——无连接词不得判」 | gate |
| 3 type_label 幻觉 | 已机械校验声明段（无条件 JSON 校验项，可安全声明） | gate |
| 4 索 evidence 路径 | 同上声明段内「未声明 evidence 路径」逐字 | gate |
| 5 索数值化置信度 | 【合法正例】「不要求特定枚举命名或数值化置信度」 | gate |

§2.3 预判的四条中，前两条经基线验证成真（写入条款一/二），后两条无误判实证但作为**预防性**合法形态保留（判据四/合法正例）——与 #30 ④「合法形态远锚=无视」权衡后近端放置。

**一轮达标，无迭代**（前四例分别用了 4/4/3/5 轮）。牙齿无一条 <5/6，vio4 反从 4/6 升到 6/6 = #28「从严多拦的全是噪声」第五实证。vio3 唯一偏差（[6] PASS、[2] 判到条款二）是引错条款而非漏判方向。

**无压跷跷板信号 → 不下沉 mech**，正好避开 §0.1 那个「statements 分支不执行 mech_checks」的结构障碍（若出现跷跷板，本例会卡在需先补 statements 侧注册表）。

**一轮达标的可归因原因**（供后续节点参考）：
1. 最高频误伤源是**判据自己的词形**（「主语」），改文本即根除——不像「发明要件」要靠双侧钉死逐个堵；
2. 前四例已把 harness 层坑填平（v2.76 framing 双态、v2.79 跨步拼合注），本例直接受益：基线里「跨子步串号/字段混入」类判词已显著少于 #3 基线；
3. 判据本身是**结构性**的（传导一致性/连接词/名词位置），比 #2 的「同义反复/稻草人」语义类判据裁量面窄。
