# u:3#2 约束验证步轮次治理（sync 一次即止 + 批量定位 + 出处复用）设计

日期：2026-08-22　分支：feat/u3-sub2-batch-locate

## 1. 背景（实证）

2026-08-22 interaction_turnover u:3#2（约束验证标注）：59 轮 / cr 2.3M /
墙钟 4.2min——轮次为同类步 4-8 倍。逐调用审计（35 Bash + 少量 Read/Edit）：

| 构成 | 调用数 | 判定 |
|---|---|---|
| codegraph 新鲜度跳舞（check→sync→再 check→换目录 sync→再 check→force re-index） | **7** | **纯浪费**——sync 报 Already up to date 但新鲜度仍过期（索引 745h），模型连试 3 种姿势 |
| 逐目标单发定位（grep 常量定义/调用面/模板宏/路径，~30 个不同目标） | ~30 | **内容必要**（候选1=枚举报告内全部年化展示入口，子1 出处是 AskUserQuestion 选项非 file:line，本步必须实证），但**形式可批量化**（无依赖的多目标可合并到单条 Bash） |
| 载荷装配 | ~4 | 正常 |

**根因二分**：不是重复 thrash（35 个命令目标全不同），是
①sync 怪癖无应对钉死；②逐目标单发 = 每轮全前缀税 ×59（cr 2.3M 主因）。

**已排除的杠杆**（三查）：
- 复用 u:1#4 取证链出处 → **不可行**：交接包只带前序节点归一化结论摘要
  （实测 data_loaders.py:166/_macros.html:57 在包内 0 命中），无出处可引；
  为此加跨节点 trace 注入机制 = 过度工程（本步墙钟仅 4.2min）。
- mech 轮次硬上限 → 不可行：append-trace 只见载荷不见过程。
- gate 变更 → 不需要：判材边界已明文「引用子1 已取证来源即合规」，
  且 constraint_verification_tool_trace 词表含「原文」——引用形态本来就过。

## 2. 方案（purpose/selfcheck 文案钉死，零 mech 零 gate 变更）

**修A codegraph 一次即止**：purpose 现有「索引过期先 sync」扩为
「sync 一次即止——sync 报 Already up to date 而新鲜度仍过期 = 留痕结论
（codegraph 仅作符号/行号指引）继续，禁 force re-index/换目录重试/重复 sync」。
（u:1#4 同会话同怪癖 4 调用收场，u:3#2 烧 7 调用 = 纯模型方差，钉死收口。）

**修B 批量定位钉死**：「多目标定位查询合并——无相互依赖的多个定位目标
合并到**单条 Bash**（`grep -n -e 模式A -e 模式B` 或多命令 `&&` 串联）；
同文件相邻段落一次 Read 不拆多次；逐目标单发仅限有依赖关系
（先定位符号才能读文件）」。预期 30 定位调用 → ~12-15。

**修C 出处复用钉死**（诚实边界版）：「子1 候选自带出处（AskUserQuestion
选中项/会话事实/Read 原文）满足 gate 明文合法形态 = 逐字引用，
**禁为『本步留痕』重跑同类验证**；仅子1 出处不足以支撑三态处置的候选
才本步补验」。

selfcheck 同步补三问。预期形态：59 轮 → ~25-30 轮，cr 2.3M → ~1.2-1.4M，
墙钟基本不变（内容工作量不变，省的是前缀税与跳舞）。

## 3. 验证

- 单元：无 mech/gate 变更，既有 1237 tests 回归全绿即可；
- 现场：文案钉死类改动按惯例登记「下一个跑到 u:3#2 的实例观察轮次构成」，
  不做种子 A/B（本步内容工作量实例间方差大，A/B 信号噪声比低——
  与 p1-sub3 条款镜像教训同型，观察轮次构成而非总账）。
